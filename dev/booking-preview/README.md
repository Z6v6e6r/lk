# Локальный стенд интерфейсов записи

Запуск из корня этого worktree:

```sh
npm exec -- vite --config dev/booking-preview/vite.config.ts
```

Адрес: http://127.0.0.1:5173/. Сервер слушает только локальный компьютер.
Стенд использует существующие React-компоненты из `src/`: создание игры,
поиск открытых игр, приглашение в игру, расписание тренировок и деталей
тренировки, афишу турниров и карточку записи на турнир. Правки компонентов
сразу обновляют открытый экран через Vite HMR.

В меню доступны шесть основных сценариев и поиск игр. Переключатель ширины
задаёт реальную ширину iframe, поэтому работают мобильные media queries.
Состояния: есть места, нет мест, уже записан, гость, загрузка, пусто, ошибка.
«Нет мест» / «Уже записан» относятся к присоединению, а не к созданию игры.
В режиме гостя можно пройти тестовую форму входа с произвольным кодом.
«Сбросить» очищает изменения тестовой записи, перезагружая iframe.
Параметры `screen`, `state`, `width` сохраняются в URL.

Данные синтетические. API заменяются только отдельной конфигурацией стенда;
обычные dev/prod-сборки не используют эти замены. Запись меняет только память
страницы. Оплата имитируется успешным результатом без платёжной ссылки.
CSP разрешает сетевые запросы только к локальному серверу. Внешние переходы,
формы, popup-окна и навигация родительской страницы ограничены iframe.
Неизвестный метод API возвращает ошибку стенда и предупреждение в консоли.

Проверка типов и отдельная сборка стенда:

```sh
npm exec -- tsc --project dev/booking-preview/tsconfig.json --noEmit
npm exec -- vite build --config dev/booking-preview/vite.config.ts
```

Результат сборки: `dist/booking-preview/`. Для работы над интерфейсом используйте
сервер разработки, а не производственный IIFE bundle.

## Матрица способов записи

Панель состоит из четырёх независимых блоков: подписка, Резидентство,
Энергия 5 и РАбуста. Владение задаётся флажками `subscription`, `residency`,
`pass`, `boost`. Старые ссылки с восемью профилями `privileges` читаются как
раньше; явные флажки имеют приоритет. Без подписки и Резидентства Буст
сбрасывается и недоступен для включения. Применимость Энергии задаётся отдельно.

Тестовые цены из предоставленной владельцем матрицы:

| Услуга | Полная цена | С Резидентством |
| --- | ---: | ---: |
| Корт целиком, за всех | 4 000 ₽ | Льготы не применяются |
| Моя доля ¼ в игре 2×2 | 1 000 ₽ | 700 ₽ (−30%) |
| Групповая тренировка | 5 500 ₽ | 2 750 ₽ (−50%) |
| Турнир | 8 000 ₽ | 4 000 ₽ (−50%) |

Это примеры отображения, а не подтверждённые действующие тарифы. Подписка
даёт бесплатное время игры или занятие согласно выбранному тарифу. После использования дневного бесплатного лимита подписка остаётся
доступной со скидкой: игры — 30%, групповые и турниры — 50%. Подходящий
абонемент отдельно списывает одно посещение. Эти варианты не объединяются
с Резидентством. Если применимой
привилегии нет, доступна полная цена; иначе она показывается зачёркнутым
ориентиром. Доступные способы остаются независимыми и выбираются явно.

Все применимые способы, включая предложения подписки и Резидентства, выбираются
радиокнопками. Выбор меняет сумму на основной кнопке и не открывает окно.
Если подписки нет, по умолчанию выбрано Резидентство, если этот способ доступен, в том числе
предложение купить его. Ручной выбор сохраняется. При неприменимом
Резидентстве выбирается первый доступный способ; весь корт остаётся без льгот.
Имеющаяся подписка с Бустом на финальном шаге показана одной карточкой
«По подписке и РАбуста» с названием тарифа и итоговой ценой. Используется
меньшая из известных цен участия. При одинаковой цене сохраняется способ
`subscription`, при дополнительной выгоде Буста — `boost`. Отдельных кнопок
подписки и Буста нет; неизвестная цена не подменяет известный платный вариант.
При Резидентстве с Бустом без подписки финальный шаг объединяет их в одну
карточку «С Резидентством и РАбуста» с итогом Буста. Предвыбор остаётся за этой
карточкой; реальный тип локального заказа — `boost`, повторной покупки
Резидентства нет. С подпиской Буст относится к её лимитам и не подменяется
сочетанием с Резидентством. Неизвестная цена Буста не убирает платный вариант.
При действующей подписке скрываем Резидентство на всех экранах обоих
этапов: создание, присоединение, сравнение и «Плачу за себя», даже после
дневного лимита или при 8 активных записях. Это также действует после
тестовой покупки подписки. Если подписка неприменима, остаётся полная цена
и подходящая Энергия 5; Резидентство не возвращаем.
Проверка владения продуктом и его покупка начинаются после «Записаться».
Открытие формы не активирует привилегию и не создаёт запись.
Цена/условия оформления привилегий не выдуманы. Неприменимые способы записи
скрыты в панели. Для исключённых групповых не показывается отдельное
уведомление об ограничениях: остаются полная цена и подходящий абонемент.

«Сравнить услуги» показывает три карточки одновременно. Новая панель также
встроена в детали игры, тренировки и турнира, в запись из списков и в
финальный шаг создания игры. `previewTransform.ts` меняет только checkout
JSX при компиляции отдельным конфигом стенда; исходники `src/` и обычные
сборки не меняются. При несовпадении ожидаемых областей JSX сборка стенда
останавливается, чтобы не показать старый и новый checkout одновременно.

Подтверждение/отмена в новой панели меняют только её локальное состояние.
Они не вызывают платёжные API, не списывают реальные посещения, не меняют
состав в других компонентах и сбрасываются при перезагрузке/смене профиля.

Проверки матрицы и областей подстановки:

```sh
node --experimental-strip-types --test dev/booking-preview/*.test.ts
npm exec -- eslint dev/booking-preview
```

Владелец сценариев — PadlHub; аудитория — локальная работа над интерфейсом.
Критерий результата — независимые сочетания привилегий для трёх услуг, явный
выбор способа, состояния недоступности и корректный мобильный вид.
Сигнал остановки — смешанный checkout или запрос к внешнему сервису.
Остановить стенд можно через Ctrl+C в терминале Vite; внешних операций
для отмены у прототипа нет.

## Подписки, дневной лимит и Буст

Правила локального стенда уточнены владельцем 11 ноября 2026:

| Тариф | Бесплатный дневной лимит | Остальные стандартные события |
| --- | --- | --- |
| Дружба (`friendship`) | Игра: своя ¼, до 60 минут | Групповые и турниры: скидка 50% |
| Дружба 2.0 (`friendship-2`) | Игра: своя ¼, до 120 минут; также «Время на друзей» | Другие турниры и групповые: скидка 50% |
| РА (`ra`) | Игра до 60 минут либо целая групповая / турнир | После лимита: скидки 30% / 50% |

Подписки: 30 дней, 30 занятий, до 8 активных записей. Чекбоксы «Занятие в
день уже потрачено» (`dailyQuota=used`) и «Больше 8 активных записей»
(`activeLimitExceeded=1`) не блокируют запись: остаются скидки 30% на личную
долю игры и 50% на групповые / турниры, кроме ПРО. На платное время сверх
бесплатного лимита игры также действует скидка 30%.

РАбуста (`boost=1`) доступна только с действующей подпиской или Резидентством:

| Основа + Буст | Бесплатный лимит |
| --- | --- |
| Резидентство | Условия РА: игра до часа или одна групповая / турнир |
| Дружба | Игра до 2 часов или 2 групповых / турнира, либо игра 1 час + групповая / турнир |
| РА | Игра до 2 часов или 2 события, включая игру 1 час + групповую / турнир; доступно ПРО |
| Дружба 2.0 | Игра до 2 часов + групповая / турнир; доступно ПРО |

Бесплатное ПРО — максимум 1 событие в день только у РА + Буст и Дружбы 2.0 +
Буст. ПРО занимает событие в общем дневном лимите, не добавляется сверху.
«Уже использовано сегодня» (`dailyUsage`) содержит ПРО и сочетания с ним;
`proQuotaUsed` выводится из этого выбора. После «2 часа игры + ПРО» у
Дружбы 2.0 нет ещё одной бесплатной групповой / турнира; у РА после
«1 час игры + ПРО» также остаётся только платная скидка. Вариант
«С Бустом — бесплатно» появляется при наличии
Буста; при исчерпанном лимите показывает применимую платную скидку.

Направление `groupCategory=pro` отключает обычные скидки подписки и
Резидентства. Прежняя категория `excluded` отключает подписку, Резидентство
и Буст для групповой. Неактивные способы и жёлтое уведомление не показываются.
«Время на друзей» задаётся отдельно через `friendsTournament=1`.

Лимиты — тестовые состояния: запись / отмена в одной карточке не меняет
дневные лимиты других карточек. Их расход задаётся в панели, не в реальном
профиле. Ссылки `daily-hour` / `daily-training` поддерживают старые сценарии;
основная панель при открытии переводит их на Дружбу.

## Подписи предложений

Если подписки у пользователя нет, предложение называется «Бесплатно при
наличии подписки». Условия тарифа, дневного лимита, доплаты и исключённой
категории по-прежнему проверяются отдельно: подпись не даёт права на
бесплатную запись. Для исключённых групповых предложение подписки скрыто.

Энергию 5 нигде не предлагаем купить вместе с записью. Строка «По абонементу
Энергия 5» видна только при наличии действующего подходящего абонемента
и положительного остатка. Иначе строка скрыта, в том числе при нулевом остатке;
продления и покупки нового пакета нет. Это правило одинаково для обоих этапов,
создания и присоединения к игре, тренировке и турниру, а также сравнения услуг.

Для игр и тренировок применимость контролируется `passFits`; обычный турнир
доступен по имеющейся Энергии 5 независимо от `passFits`. Для ПРО сохраняется
отдельная проверка применимости. В панели флажок «Есть действующая Энергия 5»
моделирует активный абонемент. Остаток `passRemaining` — 0–5, по умолчанию 3.
Показываем остаток и кнопку списания одной тренировки; после тестовой записи
остаток уменьшается на одну, при отмене возвращается. После последнего
посещения предлагаем остальные доступные способы записи, без продажи пакета.

Форма подписки показывает тарифы кнопками с ценой подписки, стоимостью участия
и общей суммой. Сначала выбран самый доступный тариф, полностью включающий
участие; если такого нет — самый доступный подходящий тариф с доплатой.
Выбор тарифа сохраняется при закрытии окна и меняет цену варианта «По подписке».
Добавление создаёт один локальный заказ «подписка + запись».
Реальная покупка, оплата, списание и активация продукта не выполняются.

## Общий стенд для обратной связи

Панель «Настройки сценария» изначально свёрнута. В шапке кратко отображаются
этап, тариф и наличие подписки, имеющиеся продукты, дневной лимит и исключения
события. Нажмите шапку (или Enter / пробел с клавиатуры), чтобы изменить настройки.
Сворачивание сохраняет значения и не перезагружает iframe или текущий шаг записи.
Кнопка копирования ссылки доступна и при закрытой панели.

Переключатель «Сейчас · без РАбуста» (`stage=current`) скрывает Буст и
исключает его из расчётов даже при ручном `boost=1` в URL iframe.
«Полный вариант · с РАбуста» (`stage=full`) открывает настройки Буста;
для его включения по-прежнему нужны подписка или Резидентство.
При смене этапа Буст сбрасывается. Ссылка сохраняет этап, экран, размер
и настройки тестового профиля; её можно скопировать и приложить к отзыву.
Это моделирование согласованных в макете правил, а не проверка действующих
условий реального аккаунта. Обратная связь на сервере не сохраняется.

### Изолированная статическая публикация

Владелец стенда — текущая задача, аудитория — коллеги для проверки интерфейсов.
Публикация разрешена пользователем на `padlhub.su`; рабочие entrypoint ЛК,
`release.json`, backend, nginx, DNS и реальные оплаты не изменяются.
Адрес поколения: `https://padlhub.su/lk/booking-preview/<version>/`.
Каждое поколение новое, без перезаписи существующего каталога.

Из чистого checkout проверенного и отправленного source-коммита:

```sh
BOOKING_PREVIEW_BASE=/lk/booking-preview/<version>/ \
BOOKING_PREVIEW_SOURCE_SHA=<full-source-sha> \
./node_modules/.bin/vite build --config dev/booking-preview/vite.config.ts
```

Загрузка включает только `dist/booking-preview/` (без исходников, sourcemap,
секретов и `.git`). Публичный `preview-release.json` содержит source SHA,
путь поколения и SHA-256 каждого файла. В статической сборке CSP запрещает
любые fetch/XHR/WebSocket (`connect-src 'none'`) и отправку форм. API и
авторизация заменены fixtures; каталог подписок — локальный snapshot.
Bootstrap iframe до импорта компонентов изолирует local/session storage
пространством ключей стенда, скрывает cookie и изолирует BroadcastChannel.
Императивные переходы из импортированных компонентов / utils переписываются
в маршруты fixture-экрана с сохранением этапа и настроек. Ссылки на внешнюю
оплату не открываются. Если изоляция хранилища невозможна, компоненты не грузятся.

Порядок публикации: подтвердить свободный destination и текущую конфигурацию
статического `/lk/`; собрать из чистого source; проверить manifest и архив;
скопировать в новый staging-каталог вне webroot; проверить хеши; атомарно
переместить только это поколение в свободный destination; прочитать все
публичные хеши и проверить оба этапа в браузере. Никакого reload/restart.
Сигнал остановки: неожиданный destination, source/hash drift, запросы к
реальным API или неработающий этап. До публикации остановиться; после —
при совпадении manifest переместить только своё поколение из webroot
в приватный backup-каталог. Старые поколения и рабочий ЛК не трогать.

## Кто оплачивает игру

На шаге даты / времени после корта выбирается «Плачу за себя» (¼ стоимости)
или «Плачу за всех» (весь корт). Выбор сохраняется до финального шага и при
возврате через «Изменить». Полная оплата за всех всегда без подписки,
Резидентства, Буста и абонементов.

В карточке личной оплаты видны базовая ¼ и цена по подписке. Резидентство
показывается только при отсутствии действующей подписки.
Имеющийся Буст объединён с подпиской (или с Резидентством, если подписки нет)
в одну строку с итоговой ценой, как на финальном шаге. Для подписки с Бустом
используется меньшая из двух известных цен участия.
Предложение подписки показывается и без её
покупки; запись потребует добавить продукт на следующем шаге.

В мастере ставка корта — 4 000 ₽/ч. Для 60 / 90 / 120 минут:

| Цена | 60 мин | 90 мин | 120 мин |
| --- | ---: | ---: | ---: |
| Весь корт | 4 000 ₽ | 6 000 ₽ | 8 000 ₽ |
| Своя ¼ | 1 000 ₽ | 1 500 ₽ | 2 000 ₽ |
| Резидентство, −30% | 700 ₽ | 1 050 ₽ | 1 400 ₽ |
| Дружба / РА, бесплатный час доступен | 0 ₽ | 350 ₽ | 700 ₽ |
| Дружба 2.0, бесплатные 2 часа доступны | 0 ₽ | 0 ₽ | 0 ₽ |

Доплата = личная доля × платные минуты / длительность × 0,7, с округлением
до копейки. Этот же расчёт используется в финальном шаге, CTA и локальном
заказе. Карточка присоединения / сравнения использует цену своего события:
например, при корте 4 000 ₽ за 90 минут доплата за 30 минут — 233,33 ₽.

С имеющейся подпиской личная доля подписана «Моя доля · по подписке».
С действующей подпиской вариант Резидентства скрыт, включая предложение
покупки; доступна подписка с Бустом, если он применим. Без подписки
предвыбрано Резидентство, если оно доступно.
Базовая сумма
показывается зачёркнутой над каждой льготной ценой. Цена всего пакета Энергия 5
не сравнивается с ценой одной записи. Неизвестные цены не заменяются нулём.

Точность расчёта денег в прототипе — до копейки; реальное распределение
округлений, расход лимитов и платёжные операции не реализованы.

## Выбор способа и добавление Резидентства

Полная цена тренировки: кнопка «Записаться за 5 500 ₽». Выбрано Резидентство:
«Записаться за 2 750 ₽». При нажатии владельцу Резидентства сразу показывается
экран оплаты 2 750 ₽. Если Резидентства нет, открывается короткое предложение
с преимуществами и кнопкой «Добавить Резидентство за 790 ₽». Она создаёт один
локальный заказ: запись 2 750 ₽ + Резидентство 790 ₽ = 3 540 ₽.

Временная цена 790 ₽ задана владельцем. Поле «Стоимость Резидентства, ₽»
сохраняется в `residencyPrice` и передаётся в iframe. Это конфигурация макета,
не загрузка фактической цены из каталога. Пустая/невалидная цена блокирует
покупку Резидентства. Сумма заказа считается в копейках.

В стенде вместо внешней платёжной ссылки открывается локальный экран оплаты
с составом заказа и итогом. Только тестовое «Оплатить» отмечает запись
оплаченной и активирует Резидентство в памяти компонента. Возврат с оплаты
и закрытие предложения ничего не активируют. Отмена записи не отменяет
уже купленное Резидентство. Выбранный способ сохраняется при входе и закрытии
промежуточного окна. Реальные платёжные ссылки, API покупки/записи и загрузка
цены Резидентства с сервера не подключены.

## Выбор подписки и РА

Резидентство оформляется в таком же отдельном полноэкранном окне после
«Записаться»: преимущества, ограничения, полная и льготная цена участия,
стоимость Резидентства и общий итог. Нижняя кнопка показывает сумму
«Резидентство + запись» и передаёт обе позиции в один тестовый заказ.
Например, для групповой: 2 750 ₽ + 790 ₽ = 3 540 ₽. Цена продукта берётся
из настройки `residencyPrice`; при неизвестной цене продолжить нельзя.
Имеющееся Резидентство не требует повторной покупки. Оба окна используют
общую раскладку с закреплённой кнопкой и клавиатурной навигацией.

После выбора «По подписке» основная кнопка «Записаться» открывает отдельный
полноэкранный экран оформления, если продукта ещё нет. Здесь можно выбрать
подходящий тариф, прочитать преимущества и ограничения, увидеть стоимость
участия, подписки и общий итог. Нижняя кнопка с итоговой суммой остаётся
видна при прокрутке и переводит обе позиции в один тестовый заказ.
Закрытие возвращает к способам записи и сохраняет выбранный тариф.
Имеющаяся подписка не требует повторной покупки. Использованный дневной
лимит сохраняется: для РА и групповой 90 минут это 23 800 ₽ + 2 750 ₽ = 26 550 ₽.

В `subscriptionOffers.ts` используются локальные цены: Дружба — 9 800 ₽,
Дружба 2.0 — 19 800 ₽, РА — 23 800 ₽. Цены Дружбы и РА прочитаны из публичного
каталога 11 ноября 2026, цена двухчасового продукта — из существующего
storefront-каталога. Доступность новых предложений имитируется. Дружба
предлагается для игр, Дружба 2.0 — для игр и «Времени на друзей», РА — для
обычных игр, групповых и турниров. Для игры 90 / 120 минут без имеющейся
подписки сначала предлагается Дружба 2.0: участие 0 ₽, покупка 19 800 ₽.
Альтернативная Дружба для 90 минут: подписка 9 800 ₽ + доплата 350 ₽ = 10 150 ₽.
На 60 минут достаточно Дружбы. При исчерпанных лимитах и длительности сверх
покрытия нулевая доплата не обещается. В ПРО обычная подписка не предлагается.

РА включает групповую / турнир целиком. Игра покрывается в пределах часа,
свыше него — доплата со скидкой 30%. Подписка активируется только после
тестовой оплаты и не аннулируется при отмене записи. Цены не запрашиваются
из iframe по сети; реальная покупка, запись и списания не выполняются.
