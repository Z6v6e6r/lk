# ЛК1 Падел Прайм Новокузнецк

Страницы для `padelprime42.ru` используют тему Падел Прайм, тенант VivaCRM `fJzpsf`
и станцию `9d43f278-a38d-4df1-ae20-5bd6d8a85261` в часовом поясе
`Asia/Novokuznetsk` (UTC+7). Публичные поиск и создание используют эту станцию
даже при переданном в URL идентификаторе другого клуба.

| Путь Tilda | Сценарий |
| --- | --- |
| `/finde_game` | Публичный поиск игр Новокузнецка |
| `/game_create` | Вход, выбор времени и создание игры для этой станции |
| `/community_join?invite=КОД` | Вход и вступление по приглашению |
| `/game_join?joinGame=ID` | Переход из поиска и из игрового приглашения |

## Сборка

`node deploy/novokuznetsk/build-pages.mjs /absolute/new-directory --preview http://127.0.0.1:24642`
собирает страницы для локального HTTP-стенда. Вызовы Viva и игрового API в таком
пакете идут на loopback.

Для сборки на домен клуба используется `--release /absolute/config.json`.
Поля JSON:

- `assetBase` — HTTPS-каталог для содержимого `assets/` с CORS для домена клуба.
- `backendBase` — HTTPS-адрес параллельного API с префиксом `/novokuznetsk`.
- `cabinetUrl` — URL кабинета на `https://padelprime42.ru`.
- `gamesMasterServiceId` — подтверждённый ID мастер-услуги Viva в Новокузнецке.
- `offerUrl`, `privacyUrl` и `consentVersion` — согласованные документы и версия согласий клуба.

Итоговый `tilda-block.html` вставляется один раз в T123 на каждой странице. Страницы
в каталоге сборки используют тот же блок для проверки. Смена версии требует
публикации `assets/release.json` вместе с IIFE-бандлами.

## Хранилище параллельного API

`node deploy/novokuznetsk/prepare-mongo.mjs --plan` печатает коллекции и индексы.
В изолированном экземпляре MongoDB база `lk1_novokuznetsk` содержит:

| Коллекция | Данные |
| --- | --- |
| `lk_games` | Игры и черновики. Уникальный ключ по `tenantKey` и `id` |
| `lk_communities` | Сообщества, приглашения и участники |
| `lk_community_rankings` | Рейтинг участников |
| `lk_community_feed` | Лента сообщества |
| `lk_community_events` | События сообщества |

Команда `--apply-local` создаёт эти коллекции и индексы в пустом локальном
экземпляре. Нужны `NVK_MONGO_ADMIN_URI` (адрес экземпляра на 127.0.0.1 с базой
аутентификации `admin`) и `NVK_MONGO_BACKEND_PASSWORD`. Учётка
`lk1_novokuznetsk_backend` получает `readWrite` только на `lk1_novokuznetsk`.
Для локальных тестов используется MongoDB 8.0.5. Схема содержит проверенные
индексы игр и ленты из ЛК1 и дополнительные индексы сообщества по формам запросов.
В неё загружаются только тестовые данные для локальной проверки.

## Подключение бэкенда

Параллельный API должен проверять станцию сервером, а профиль игрока получать
в тенанте `fJzpsf`. Для страницы поиска нужен `GET /lk/games`, для создания
`GET /lk/onboarding/stations` с мастер-услугой и подуслугами станции, а также
маршруты создания и подтверждения игры. Для приглашения нужны
`GET /lk/communities?view=summary` и `POST /lk/communities/join-by-invite`.
Все маршруты доступны через базовый URL Новокузнецка. Для реального входа
нужен клубный `/lk/analytics/auth-consents` с собственной коллекцией согласий
и подтверждённый redirect URI в Keycloak `widget`.

Существующий маршрут `/pade-prime` использует общий Mongo-клиент и общий
подграф проверки профиля. Новый маршрут требует отдельный рантайм или явно
изолированные конфиг-узел MongoDB и подграф авторизации. До подключения
проверяются автовступление, отказ для другого тенанта и станции, выбор времени
UTC+7, сохранение без дубликатов и повторные запросы при временной ошибке.
В этой сборке отключена раздельная оплата. Для открытия реального создания
нужно подтвердить карточку услуги, тарифы, классификацию открытой игры и
согласованный сценарий бронирования Viva.
