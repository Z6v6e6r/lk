# LK1: доплата по клубной подписке «Дружба Топократы» (2026-09-25)

## Зачем

Поколение `lk1-topokraty-friendship` (2026-09-26) добавило правило клуба: первое событие дня
по клубной подписке списывает посещение (свободный час), а минуты сверх часа оплачиваются как
доплата за 1/4 корта. Оно было собрано и откачено, потому что **денежный мандат клуба в
установленном flow отсутствовал**: живое тело шлюза использовало только `lk1EventPaymentBinding`
(6 вхождений), тогда как `lk1ClubEventPaymentBinding` и `lk1EventPaymentQuoteBinding` из PR #153
жили только в исходниках. Любая доплата (`amountMinor > 0`) не проходила денежный readback, то
есть собрать 1/4 корта было нельзя.

Это поколение (`lk1-topokraty-copay`) ставит мандат и контур вместе, поверх установленного
поколения инцидента 2026-09-25 (`9d2487a4…`).

## Деплой и откат

```bash
NODE_RED_LK1_TOPOKRATY_COPAY_DEPLOY=CONFIRM_147 npm run nodered:lk1-topokraty-copay:deploy-147
NODE_RED_LK1_TOPOKRATY_COPAY_ROLLBACK=CONFIRM_147 npm run nodered:lk1-topokraty-copay:rollback-147 -- <stamp>
```

Откат **ordered**: сначала возвращается 7-правильный payload (revert-кандидат `278a15c8…`),
затем восстанавливается flow `9d2487a4…`. Обратный порядок оставил бы глобал с клубным
продуктом, а восстановленный оценщик — без клубной ветки.

## Остаточные риски

* Приёмка на реальном клубном абонементе (клиент `79104303190`): час → 0 ₽/посещение, 120 минут →
  доплата 1/4 корта, исчерпанный день и ≥4 активных записей. До деплоя не проверяемо на проде.
* Клубный продукт должен быть оформлен на клиента в Viva; иначе ветка клуба не применится и
  событие остаётся разовым (это ожидаемое поведение).
* Покупка абонемента под конкретное занятие по-прежнему создаётся браузером прямо в Viva и этим
  контуром не переносится.
* Направление 6233 зашито в правиле клуба; новое направление Топократов потребует расширения
  списка и нового поколения.
