# Витрина расписания в Tilda: четыре блока T123

Монолитная вставка разбита на независимые блоки, чтобы:

- настройки правил человек, который не трогает скрипты (блок 1);
- витрину можно было поставить в любое место страницы, а служебные скрипты —
  один раз на весь сайт;
- блоки не зависели от порядка скриптов на странице.

## Состав

| Файл | Что это | Сколько раз | Куда ставить |
| --- | --- | --- | --- |
| `1-settings.html` | Настройки: категории, бейджи, лимиты, внешний вид | 1 раз | Выше витрины (или один раз на весь сайт) |
| `2-schedule.html` | Витрина: контейнер + загрузчик бандла | 1 раз на страницу | Где должен быть слайдер |
| `3-booking-popup.html` | Попап записи VivaCRM (инстанс `atlanty`) | 1 раз | Внизу страницы (или в футере сайта) |
| `4-theme.html` | Оформление: CSS-переменные | по желанию | Рядом с блоком 1 или 2 |

Каждый файл — это отдельный блок Tilda **T123 («HTML-код»)**. Вставляется целиком,
вместе с комментариями.

## Порядок и правила

1. **Блок 1 — выше блока 2** (на той же странице). Блок 2 ждёт `DOMContentLoaded`,
   поэтому даже при обратном порядке настройки успеют примениться, но так читаемее.
2. **Блок 3** можно ставить где угодно после блока 1 — он не зависит от витрины,
   потому что сначала ставит свою инициализацию в очередь и только потом грузит бандл.
3. Если блока 1 нет вообще, витрина покажет корпоративную категорию по умолчанию
   (направление «Атланты», тип «Корпоративные клиенты»).
4. Блок 2 сам дожидается появления своего контейнера, поэтому устойчив к ленивому
   рендеру блоков в Tilda.

## Вариант «на весь сайт»

Служебные блоки можно поставить один раз на все страницы —
**Настройки сайта → Ещё → HTML-код для вставки внутрь BODY**:

- туда: блок 1 (настройки), блок 3 (попап записи), при желании блок 4 (оформление);
- на конкретную страницу: только блок 2 (витрина).

Тогда на нужной странице остаётся один короткий блок, а категории и бейджи правятся
в одном месте.

## Что менять в блоке 1

```js
var ATLANTY_CATEGORIES = [
  { directionId: 6152, typeId: 2349, label: "Клубное мероприятие", badge: "Бесплатно по подписке" },
  { directionId: 5278, typeId: 839,  label: "Время на друзей",      badge: "50% скидка по подписке" }
];
```

| Поле | Значение |
| --- | --- |
| `directionId` | `direction.id` из Viva — уходит в серверный фильтр `directions` |
| `typeId` | `type.id` из Viva — нужен попапу записи, чтобы он видел событие |
| `label` | текст пилюли над заголовком (по умолчанию — название направления) |
| `badge` | текст бейджа на шапке карточки (пусто — бейджа нет) |
| `enabled` | `false` временно выключает категорию |

Остальные ключи конфига: `maxEvents` (всего карточек), `maxPerCategory` (сколько
из каждой категории; `0` — без квоты), `daysAhead` (горизонт), `cardsPerView`
(сколько карточек в ряд с 768px; `0` — фиксированная ширина, на мобильном
всегда одна карточка и свайп), `pillIcon`, `avatarMode`,
`seatsStyle`, `levelStyle`, `detailModal`, `images`, `imagePick`, `title`,
`vivaInstance`, `booking` (`"viva"` — попап VivaCRM, `"lk"` — окно записи ЛК1
с контуром ограничений; подробности — `docs/ATLANTY_SCHEDULE_WIDGET.md`).

**Правки в блоке 1 не требуют пересборки бандла** — конфиг читается на странице.
Так же добавляется новая категория (например «Патриоты», когда направление
появится в Viva).

## Проверка после вставки

1. Открыть страницу, убедиться, что секция пустая, а не с ошибкой загрузки.
2. В консоли не должно быть `Не удалось загрузить расписание`; если есть — проверить,
   что `https://padlhub.su/lk/atlanty-schedule.js` отдаёт 200.
3. Клик по карточке открывает карточку события, кнопка «Записаться» — попап Viva
   на этом событии.
4. Если попап открывается, но без выбранного события — значит блок 3 не подключён
   или виджет Viva не успел навесить обработчики; проверьте блок 3.

  T123). Удобен, если нужен один блок и не важны раздельные настройки.
