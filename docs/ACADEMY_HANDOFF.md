# Академия «Родина»: передача и развёртывание

## Версия и назначение

Это кастомный React/TypeScript кабинет академии для Viva tenant **005JDA**.
Tenant получен из предоставленного публичного виджета:
https://supadb.vivacrm.ru/storage/v1/object/public/widgets/1ef6433f-a5de-4a77-9784-73be90273f59.js

Исходники: https://github.com/Z6v6e6r/lk, ветка
`codex/academy-preview-20261110`. Точный SHA находится в `UPSTREAM.json`
передаваемого архива. Доступ к частному GitHub-репозиторию владелец выдаёт отдельно.
Для этой сборки дополнительный стандартный Viva widget script не требуется.

Публичный профиль сборки: `config/academy-005jda.public.json`. В нём нет секретов.
Профиль фиксирует tenant, URL кабинета, Viva API и отдельный backend академии.
Исходный tenant ПадлхАБ `iSkq6G` сохраняет прежние настройки и ключи сессии.

## Что входит

- Вход Viva, профиль, текущие/прошедшие записи, абонементы.
- Каталог подписок из Viva v2 tenant 005JDA и создание покупки в этом же tenant.
  При неопределённом результате создание не повторяется автоматически.
- Согласия по документам «Родины» и отдельный серверный аудит.
- Чтение сообществ, в которых состоит подтверждённый пользователь академии.
- Регистрация/удаление native push-токенов с проверкой владельца.
- Отдельная минимальная серверная телеметрия; Firebase ПадлхАБ не используется.

Сообщества начинаются пустыми. Старые записи/сообщества/клиенты ПадлхАБ не
переносятся. Учётная запись пользователя должна существовать в tenant 005JDA.
Браузерный кабинет не превращается в нативное приложение: реальная доставка
push требует native-клиента, его FCM-конфигурации и отправителя, читающего
академическую коллекцию. Рассылки/сообщения этим модулем не отправляются.

Заморозка, экран расписания, переход к играм и часть новостей остаются
прототипами прежнего кабинета; перенос tenant не реализует новые UI-функции.

## Быстрый старт из полного репозитория

Нужны Node.js 22.12+ (рекомендуется Node 22 LTS), npm и Git.

```sh
git clone --branch codex/academy-preview-20261110 https://github.com/Z6v6e6r/lk.git
cd lk
# При необходимости: git checkout <SHA из UPSTREAM.json>
npm ci
node --experimental-strip-types scripts/build_academy_tenant.mjs
```

Скрипт требует чистый Git checkout, проверяет конфигурацию, TypeScript и собирает
только академию в `dist/academy-005jda/`. Для публикации используются три файла (JS внутри неизменяемого каталога версии):

```text
index.html
release-ffc-academy-dev.json
releases/<version>/ffc-academy-lk-dev.js
```

Корневой `ffc-academy-lk-dev.js` в build output оставлен для совместимости
с проверкой `assert-clean-deploy`; при обновлении существующего сайта этот alias
не заменяется. В передаваемом `frontend-dist/` его нет.

Манифест содержит SHA исходников, tenant, SHA256 публичного профиля и JS. Суффикс
`dev` унаследован от существующей сборки и не делает данные/покупки тестовыми.

В отдельном архивном проекте используйте `npm ci` и `npm run build`. Если архив
распакован без Git, сначала `git init`, `git add .`, `git commit -m "Import academy"`.
Новые изменения тоже нужно коммитить перед release build. `.env` и секреты в Git
не добавляются; в передаваемом проекте используются только публичные значения
из JSON-профиля.

## Настройки для другого домена

В `config/academy-005jda.public.json` поменяйте:

- `VITE_CABINET_URL`, `VITE_SUCCESS_URL`, `VITE_FAIL_URL` — точный HTTPS URL HTML.
- `VITE_ACADEMY_BACKEND_BASE` — HTTPS origin backend плюс фиксированный путь
  `/lk/analytics/academy-005JDA`.
- Остальные URL текущего хоста — адреса вашего размещения. Overlay-URL в профиле
  зарезервированы общей сборочной проверкой; дополнительные overlay-модули в
  эту версию кабинета не входят.

Владелец Viva/Keycloak должен разрешить точный OAuth callback с путём страницы
и `?authMode=viva`, а также Web Origin нового домена. Provider/API CORS и возврат
после авторизации проверяются отдельно. Сам JSON-профиль таких прав не выдаёт.
Все `VITE_*` видны посетителю браузера; пароли, service-account, Mongo URI и
серверные ключи туда не помещаются.

Утверждённые документы:

- https://cg178013.tw1.ru/docs/service-rules.pdf
- https://cg178013.tw1.ru/docs/privacy-policy.pdf

Версия комплекта: `2026-11-10-rodina`. При изменении документов обновляйте
серверный и клиентский общий контракт `src/services/academyTenantContract.ts`.

## Backend: отдельная вкладка Node-RED

Нужны Node-RED и существующий `node-red-contrib-mongodb4` (проверенный сервер
использует ветку 3.4). MongoDB credentials в архив не включены. Импортируемая
вкладка ссылается на выбранный существующий Mongo client configuration node;
его настройки и пароли не копируются и не заменяются.

Исходники: `scripts/lib/academyTenantBackend.mjs` и
`scripts/patch_nodered_academy_flow.mjs`. Последний создаёт **кандидат** от явного
свежего flow-файла, не меняет исходный файл и сам ничего не публикует:

```sh
node --experimental-strip-types scripts/patch_nodered_academy_flow.mjs \
  /private/fresh-flows.json /private/academy-candidate.json EXISTING_MONGO_CLIENT_ID
```

Полный production flow — приватный рабочий preimage, не часть передаваемого
архива. Для импорта только нового модуля сформируйте nodes через экспорт
`buildAcademyTenantNodes(MONGO_CLIENT_ID)`; в пакете есть отдельный пример
`backend/academy-005JDA.nodes.import.json` с placeholder Mongo ID.

На целевом Node-RED выберите правильный Mongo client. Разрешённые origin задаются
переменной вкладки `ACADEMY_ALLOWED_ORIGINS` (через пробел/запятую). По умолчанию
разрешены текущий preview origin и `https://cg178013.tw1.ru`.

Все маршруты имеют префикс `/lk/analytics/academy-005JDA`:

| Метод | Окончание пути | Назначение |
|---|---|---|
| GET | `/health` | Наличие модуля и версии политики; не доказывает Mongo write |
| POST | `/auth-consents` | Идемпотентный аудит канонических согласий |
| GET | `/communities` | Только сообщества подтверждённого клиента |
| POST | `/push/register` | Регистрация native device token владельца |
| POST | `/push/unregister` | Удаление только своего native device token |
| POST | `/events` | Авторизованная минимальная телеметрия |

Кроме health/OPTIONS, операции требуют Bearer. Сервер проверяет его через
Keycloak userinfo и профиль Viva **005JDA** до Mongo. Tenant/subject/clientId из
тела запроса или query не дают прав. Старый tenant и чужой субъект отклоняются.

Коллекции:

```text
academy_005JDA_auth_consents
academy_005JDA_communities
academy_005JDA_push_tokens
academy_005JDA_analytics
```

В сообществе для отображения нужны `tenantKey: "005JDA"` и активный элемент
`members` с `clientId` из подтверждённого Viva profile и `status: "ACTIVE"`.
Создание/миграция сообществ — отдельная административная операция; автоматического
копирования чужих данных нет. Общий sender ПадлхАБ не подключается к этим
коллекциям автоматически.

## Порядок публикации

1. Зафиксировать исходники и профиль; собрать и проверить манифест/хеши.
2. Сохранить свежий backend preimage и frontend backup. Проверить отсутствие
   конфликтующих маршрутов/узлов и точную Mongo-привязку.
3. Авторизованно импортировать только новую вкладку и проверить `/health`, CORS,
   отказ без токена/со старым tenant и готовность Mongo connection.
4. Сначала разместить `releases/<version>/ffc-academy-lk-dev.js` и сверить
   локальный/серверный/публичный SHA256. Путь версии неизменяемый: при отличающихся
   байтах по существующему пути остановиться, не перезаписывать. Для существующей
   ссылки заранее скопировать проверенный старый JS в путь его старой версии.
   Корневой старый JS оставить без изменений для уже открытых старых HTML. Затем
   атомарно заменить манифест и HTML отдельными rename, HTML последним. Старый и
   новый versioned JS должны оставаться доступными: это защищает два отдельных
   HTTP-запроса даже при переключении между ними. Одной атомарной замены каталога
   для этого недостаточно. Для HTML/манифеста отключить кэш.
5. Проверить возврат OAuth и загрузку данных реального пользователя 005JDA.
   Покупки/записи не создавать лишь ради smoke. Проверка оплаты — отдельный
   согласованный сценарий с учётом реальных денег.

Активация на существующем сервере — отдельное разрешённое действие, не команда
сборки. Текущий Node-RED Admin API требует авторизацию (при проверке HTTP 401).
Архив не содержит admin access token, SSH-ключи, Mongo credentials или реальные
данные клиентов. Подготовленный frontend нельзя объявлять полностью работающим
на новом tenant до активации backend и реального входа.

При откате сначала верните прежние frontend HTML/манифест; старый корневой alias
и оба неизменяемых каталога версий сохраните. Затем отключите
только добавленную вкладку при совпадении её ожидаемых хешей. Записанные согласия
и другие данные не удаляйте. Чужие изменения в flow не перезаписывайте.

## Проверки разработчика

```sh
node --experimental-strip-types --test scripts/tests/academyTenantBackend.test.mjs \
  scripts/tests/academyTenantIsolation.test.mjs
```

Тесты используют вымышленные токены/ответы и не создают реальные оплаты,
сообщения или записи. Секреты для сборки не требуются. Для правок UI смотрите
`src/academy/`, для tenant/юридической политики — общий contract и публичный JSON.
