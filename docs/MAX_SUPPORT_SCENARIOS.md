# MAX Support Scenarios

## Пользовательские сценарии, которые теперь учтены

1. Новый пользователь отправляет `/start` в MAX.
   Сценарий: бот просит поделиться контактом, диалог еще не авторизован.

2. Пользователь пишет текст до шаринга номера.
   Сценарий: сообщение сохраняется в `UNASSIGNED`-диалог, в ответ приходит просьба поделиться номером.

3. Пользователь делится контактом.
   Сценарий: номер нормализуется, клиент переводится в `VERIFIED`, если номер уже существовал у другого клиента, профили объединяются.

4. Пользователь после контакта еще не выбрал станцию.
   Сценарий: бот просит выбрать станцию, сообщения продолжают сохраняться.

5. Пользователь выбирает станцию.
   Сценарий: `UNASSIGNED`-диалог переносится на выбранную станцию, история до авторизации не теряется.

6. Пользователь пишет после выбора станции.
   Сценарий: сообщение попадает в station-dialog, становится непрочитанным для сотрудников станции.

7. Пользователь несколько раз пишет до ответа сотрудника.
   Сценарий: считается ожидание первого ответа, а не только факт последнего сообщения.

8. Сотрудник отвечает из админки.
   Сценарий: сообщение сохраняется, считается `first response`, команда уходит в `support outbox`, MAX flow подтягивает и отправляет ее в MAX.

9. Один клиент использует несколько телефонов.
   Сценарий: все номера хранятся в одном `support_client`, primary phone используется как ключевой в UI.

10. Один клиент пишет из разных каналов.
   Сценарий: в профиле клиента сохраняются channel identities, диалог становится мультиканальным.

11. Приходит email по известному email/телефону.
   Сценарий: событие можно записать через `POST /api/support/dialogs/events`, оно появится в истории как `EMAIL`.

12. Приходит звонок из Mango/Bitrix.
   Сценарий: событие можно записать через тот же endpoint, оно появится в истории как `CALL`.

13. У клиента уже есть диалог по станции и есть временный `UNASSIGNED`.
   Сценарий: при авторизации/выборе станции временный диалог сливается в station-dialog.

14. Диалог без телефона должен быть виден в ЦУП.
   Сценарий: такие диалоги считаются `UNVERIFIED`, видны в списке и выделяются в UI.

15. Нужна аналитика за день.
   Сценарий: `GET /api/support/analytics/daily` отдает срез по станциям, темам, приоритетам, каналам и времени ответа.

## Технические точки

- `ph-ab/src/support/*`
  Новый support backend.
- `ph-ab/client-sdk/phab-admin-panel.js`
  Переключен на support API для вкладки переписки и аналитики.
- `lk_max_webhook_nodes_import.json`
  Единый импортируемый MAX flow для Node-RED.
