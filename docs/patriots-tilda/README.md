# «Предприниматели-патриоты»: замена блоков Tilda

Страница: `https://padlhub.ru/predprinimateli-patrioty`. Это исходники блоков T123 для **черновика** страницы. Не публиковать до выполнения условий ниже: текущий продукт VivaCRM ещё не покрывает направление `5278`, а цену записи должен подтвердить сервер. В блоке событий `PH_PATRIOTS_ENTITLEMENTS_READY = false`, поэтому даже с боевым бандлом кнопка подписки остаётся выключенной, а условия на странице и карточках помечены как подключаемые.

## Данные и условия

ID и типы направлений проверены по публичному VivaCRM API 2026-09-29. Цены записи ниже — согласованные целевые условия, которые ещё должен подтвердить сервер:

| Направление | Viva ID | Тип занятия | Целевая цена по «Дружба.Патриоты», пока не действует |
| --- | ---: | ---: | ---: |
| Предприниматели-патриоты: игры | `6181` | `2349` | 0 ₽ |
| Предприниматели-патриоты: турниры | `6306` | `2349` | доплата 2 750 ₽ |
| Предприниматели-патриоты: тренировки | `6307` | `2349` | доплата 2 750 ₽ |
| Время на друзей, **все** события направления | `5278` | `839` | доплата 2 750 ₽ |

Точное имя направления тренировки в Viva сейчас содержит опечатку «Пердприниматели…»; страница показывает исправленный текст. За 120 дней Viva вернула 137 событий: 3 игры, 1 турнир, 1 тренировку и 132 события «Время на друзей». Витрина ограничивает показ до 6 ближайших на категорию; это не ограничивает право на остальные события `5278`.

Продукт `37ab3713-4431-4815-96ba-d7ece76a9241`: «Дружба.Патриоты», 6 800 ₽, 30 посещений / 30 дней. В публичном продукте пока указаны только направления `6181`, `6306`, `6307` и тип `2349`. `5278` и тип `839` **отсутствуют**. Сценарий доплаты на всех событиях `5278` пока не может считаться действующим.

## Замена на странице

Текущая страница содержит 13 T123 плюс служебный T886. Сохранить существующие блоки CSS, 7 блоков изображений, шапку и сообщество. В редакторе Tilda заменить **содержимое** указанных T123; идентификаторы ниже взяты из опубликованного HTML, в редакторе удобнее также сверять по тексту блока.

| Блок | Файл | Результат |
| --- | --- | --- |
| `rec4149515601` | `1-hero.html` | 6 800 ₽ / 30 дней, условия четырёх направлений, одна кнопка оформления |
| `rec4149533401` | `2-events.html` | живое расписание Viva с записью через окно ЛК1 |
| `rec4149540501` | `3-footer.html` | заключительный CTA без старого окна-заглушки |
| новый T123 перед событиями | `4-theme.html` | красная палитра и адаптивная ширина карточек |
| `rec4149547901` | `5-page-controller.html` | изображения, якоря, мобильный первый экран, загрузка витрины и оформление `patriots` |

Не вставлять целый HTML опубликованного блока `<div id="rec…">`: в T123 вставляется только содержимое файлов. Не менять блоки base64-медиа и `rec2215511411` (куки/Метрика).

## Связка

- Расписание использует существующий `/lk/atlanty-schedule.js`, конфиг `booking: "lk"`, направления `[6181,6306,6307,5278]`, типы `[2349,839]`. По карточке открывается окно записи ЛК1.
- Оформление использует боевой `/lk/subscription-storefront/subscription-storefront.js`. Контроллер принимает только `checkoutVersion === 1`, `checkoutChannel === 'prod'` и `supportsCheckoutOffer('patriots')`; затем вызывает `openCheckout('patriots')` и при возврате `resumeCheckout('patriots')`.
- Оффер покупает именно Viva подписку `37ab…`, а не обычную «Дружбу», без счётчика LK и без годового варианта. Перед транзакцией витрина читает публичный продукт Viva и сверяет ID, цену 6 800 ₽, 30 дней, 30 посещений, четыре направления и два типа; текущий ответ Viva не проходит эту проверку. После создания транзакции витрина проверяет поле `toPay` до перехода в банк. Попытка сохраняется до POST и не отправляется повторно после неопределённого результата.

## Условия перед публикацией и проверка

1. В VivaCRM добавить **ко всей подписке** направление `5278` и тип `839`, сохранить действующие `6181`, `6306`, `6307`, `2349`. Проверить, что подписка предлагается на примере события каждого из четырёх направлений. Это изменение действует на все события направления `5278`.
2. Настроить и проверить серверное правило записи: игра `6181` — 0 ₽ по действующей подписке; `6306`, `6307`, `5278` — ровно 275 000 копеек доплаты. Проверить цену предпросмотра и фактический запрос записи, истёкшую/чужую подписку, исчерпанные посещения, повторный запрос, ошибки Viva. Сейчас Node-RED LK1 знает отдельное правило только для «Дружба Топократы»; текущий патч страницы сам по себе правило «Патриотов» не создаёт.
3. Развернуть прошедший проверки боевой бандл подписок на `/lk/subscription-storefront/`; сверить `/lk/release.json`, `release.json` витрины, хэши и фактический `supportsCheckoutOffer('patriots')`. Даже после этого клиентская проверка публичного продукта Viva должна успешно пройти до появления цены в диалоге.
4. В черновике Tilda вставить блоки в указанном порядке, проверить мобильный/desktop, пустое и ошибочное расписание, клавиатурную навигацию, реальные события всех направлений. Без создания транзакции проверить по публичному ответу Viva 6 800 ₽ / 30 дней / 30 посещений и все направления. После доказанного серверного правила и публичного продукта изменить только `PH_PATRIOTS_ENTITLEMENTS_READY = false` на `true` в блоке событий и проверить появление кнопки и исчезновение пометки «после подключения» и «Условия подключаются».
5. Только после этих проверок опубликовать страницу и проверить опубликованный HTML, запись, возврат из банка и итоговую цену. Проверка банковского экрана требует создания транзакции и относится к отдельно разрешённому платёжному сценарию. Публикация, боевой платёж и изменение продукта VivaCRM требуют отдельного разрешённого перехода.

Публичный HTML и редактор Tilda — разные состояния. Наличие блоков в репозитории, успешная сборка витрины и сохранение черновика не подтверждают публикацию.
