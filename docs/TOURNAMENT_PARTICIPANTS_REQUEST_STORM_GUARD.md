# Tournament participants request-storm containment

## Scope

The protected read route is
`GET /lk/tournaments/participants?exerciseId=<uuid>`. The explicit refresh
route is `POST /lk/tournaments/participants/refresh?exerciseId=<uuid>` with the
same `exerciseId` in the JSON body.
The public tournament list must not hydrate participant rosters. It uses the
participant count already present in the tournament summary. A roster request
is allowed only after a user opens one tournament detail.

## Application limits

The Node-RED v2 flow applies these limits before Viva client lookups:

- only a canonical Viva exercise UUID is admitted; synthetic/manual IDs return
  `400` before cache state, profile lookup, or any Viva request is created;
- per-exercise adaptive refresh: 60 seconds after a cold/changed roster,
  120 seconds after the first unchanged refresh, and 300 seconds after two or
  more unchanged refreshes;
- response cache: 10 minutes stale, at most 500 exercises;
- stale-while-refresh: a stale response is returned while one refresh runs;
- at most 8 cold exercise refreshes globally;
- at most 3 Viva client-detail requests concurrently;
- client-detail queue: at most 30 entries and 4 seconds of waiting;
- client-detail cache: 30 minutes, at most 2,000 clients;
- response/fetch capacities are bucketed at 100 and 200; a smaller cache entry
  never satisfies a larger request, while a larger entry is safely sliced;
- the refresh-owner lease is 30 seconds; same-key cold duplicates fail fast
  with `429`, matching `Retry-After` and JSON `retryAfterMs` values;
- a circuit opens for 30 seconds after two upstream failures.

Only the refresh owner calls Viva and waits for the result. Concurrent callers
receive the available cached roster and never clear another caller's in-flight
lock. The adaptive state (`fingerprint`, `unchangedCycles`, `nextRefreshAt`) is
server-side and keyed by `exerciseId`, so staggered browser tabs cannot increase
the Viva refresh frequency.

The explicit POST refresh is available only to an authenticated Viva profile
whose custom field `e17a32f3-65f7-47c5-bda1-33d79932c884` resolves to
`проводит турниры`. It refreshes one exercise, shares the same single-flight,
global overload and circuit guards, and has a 30-second per-exercise cooldown.
Its response is an envelope with `refreshed`, `reason`, `exerciseId`,
`participants`, `refreshedAt`, and `retryAfterMs`; the GET response remains an
array for backward compatibility.

The public response strips phone numbers. Cache state is exposed in
`X-LK-Participants-Cache` for the targeted nginx access log.

At the final response boundary, the terminal removes `Connection`,
`Content-Length`, and `Transfer-Encoding` case-insensitively. GET, manual
refresh, fallback, and early validation responses keep their status, payload,
and application headers while leaving HTTP framing to Node-RED.

## Nginx guard

Install `scripts/nginx/lk-tournament-participants-guard.conf` in the nginx
`http` context and place
`scripts/nginx/lk-tournament-participants-location.conf` inside the
`padlhub.su` server block. The GET edge limit is 60 requests per minute per IP
with a burst of 20. The explicit POST refresh has a separate 10 requests per
minute per IP zone with a burst of 3. Both return `429` when exceeded.

Always run `nginx -t` before reload. The focused log is:

```text
/var/log/nginx/lk_tournament_participants_access.log
```

Useful cache values are `hit`, `miss`, `stale-refreshing`, `stale-overload`,
and `stale-if-error`.

rollout, pull and verify the current live flow again. If its SHA differs from

## Acceptance checks

- the public list renders without roster requests for every card;
- opening one card performs one abortable, no-retry roster request;
- the opened booking-backed roster polls adaptively at 60, 120, then at most
  once per 300 seconds while unchanged, and stops when the modal closes, the
  roster becomes manual, or the five-minute LK idle guard activates;
- hot concurrent requests are served from cache;
- the explicit refresh button is visible only to a tournament host, refreshes
  one Viva exercise, and respects the shared single-flight and cooldown;
- a manual/local roster never calls either participants route;
- response framing headers are removed without changing the response contract;
- cold overload returns stale data or `429` instead of accumulating waiters;
- Node-RED RSS stabilizes and other LK routes stay responsive;
- public roster payload contains no phone field.
