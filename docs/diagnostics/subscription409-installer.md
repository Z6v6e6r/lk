# Scoped subscription409 runtime installer

Owner: LK1 backend / operator of server147. Audience: release and incident operators.
This change builds on PR354, already in main, and adds a scoped adapter, offline
packet builder and guarded settings/runtime transaction. It does not merge,
upload, install, restart, dispatch a workflow or contact production automatically.

The adapter accepts only exact `POST /lk/subscription-bookings`, caller `http`,
the three request-operation find steps and `booking_finalize` with status409.
Split/training/create-owner callbacks and other observer APIs are inert. It
installs no middleware, headers, key, network route, database collection or index.
The sink emits sanitized finalizer409 JSON and suppression aggregates through the
existing PM2 logger. Router snapshots consume the same600/minute stage budget;
suppression counts are stage events, **not** request/409 counts. Missing traffic
or suppression cannot establish zero refusals. Future enum values remain UNKNOWN.

## Offline preparation

No new dependency is installed; the builder uses the existing locked esbuild.
From a clean, pushed, reviewed source with successful CI, capture a fresh private
snapshot outside **all** Git worktrees. The directory must be0700, owned by the
operator; files must be regular0600 single-link files:

- `settings.js`: exact current settings bytes, kept private because they may contain credentials.
- `flows.json`: exact source used only to pin unchanged flow and reachable hook hashes.
- `metadata.json`: `sourceKind=live-147`, `sourceHost=lk-primary-147`,
  `settingsSha256`, `flowSha256`, `machineSha256` (hash of raw `/etc/machine-id`),
  `process` (`pid`, `restartCount`, `status=online`), `hooks` (`router`, `finalize`
  function hashes), `preservedFiles` (exact paths/hashes of existing auth helpers),
  `collectedAtMs` and `coordinatedRestartApproved=true`.

The last field attests an operator-agreed restart window with all competing
writers quiesced; it is not generated by the builder and does not itself grant
live authority. Preparation without that agreement must not fabricate it.

```sh
node scripts/prepare_subscription409_runtime.mjs /private/snapshot /private/new-packet
```

This command only creates private local files. It never executes the supplied
settings. The packet contains `observer.cjs`, `installer.cjs`, exact before/after
settings, canonical `contract.json` and source/dependency/lock/bundler provenance.
The settings delta is generated again and compared by the installer; it preserves
every original byte and adds only the integrity-checked registration suffix.
No flow body is replaced. Baseline settings/flow must already be protected0600
files; the installer refuses incompatible permissions instead of changing them.

The contract pins target, machine, source SHA, process identity, source/candidate
settings, unchanged flow, enabled reachable hooks, preserved auth helpers, both
artifact hashes and generation. `apply` rejects snapshots older than30minutes.
An existing observer/marker is refused; v1 activates an absent observer, rather
than silently replacing another installation. A later version needs its own
reviewed upgrade/deactivation plan and fresh preimages.

## Separate activation authority

The following commands are for a later explicitly approved operation only. This
PR and green CI do not authorize their execution. Before any execution:

1. Verify the immutable installer hash against the approved contract **before**
   running it. Source and package must be clean, pushed and reviewed; preserve
   restricted backups and configure existing log retention/permissions.
2. Review the live startup/inflight inventory. The preparation audit saw eight
   enabled inject-once nodes; restart can repeat existing startup work. Do not
   disable them or mutate workers/queues under this diagnostic authorization.
3. Agree the exact window and ordered apply/rollback with the owner of147.
   Quiesce legacy/direct writers. The runtime-hardening installer, older Viva-token
   deploy and projection cutover paths do not all honor the common lock/lease.
   Direct `pm2`/editor operations remain outside cooperative serialization.
4. Distribute the reviewed common flow/editor lease reader from this source to
   relevant operators. It rejects v4 **before** hardlink recovery or expiry cleanup.
   Do not use an old reader, manually delete a lease or treat its preflight as
   read-only. The new installer refuses all foreign/expired leases without cleanup.

On the approved server, with the packet staged privately and its digests checked:

```sh
node /private/packet/installer.cjs status /private/packet <contract-sha256>
PADLHUB_SUBSCRIPTION409_INSTALL=CONFIRM_147 node /private/packet/installer.cjs apply /private/packet <contract-sha256>
# After a full15minute soak and the passive checks below:
PADLHUB_SUBSCRIPTION409_INSTALL=CONFIRM_147 node /private/packet/installer.cjs finish /private/packet <contract-sha256>
```

CLI admits only root/Linux, the exact machine and approved contract/installer
hashes, fixed `/root/.node-red` and `/opt/padlhub-lk1-409-diagnostics/releases`.
Mutation opt-in is mandatory. `status` reads only; no cleanup or PM2 command.
Mutating commands exec under the real shared `.padlhub-reviewed-flow-deploy.lock`
using `flock -n -F`; the child verifies its own PID/device/inode WRITE lock in
`/proc/locks`. An environment/argv marker cannot substitute for the kernel lock.

## Durable transaction and checks

Private contract, before/after settings and intent become durable before an
exclusive v4 `subscription409-runtime` lease is published at the common lease
path. It has no timeout cleanup. The complete immutable bundle is durable before
atomic settings publication. Existing same-hash artifacts are reused and never
deleted by rollback. Startup verifies artifact mode/owner/realpath/hash **before**
require. Factory failure preserves the old global context and emits only the
fixed `OBSERVER_UNAVAILABLE` enum, allowing business startup to continue.

Before the single PM2 call, restart intent is durable. Timeout/error/process
ambiguity retains the lease; `apply` will not repeat the restart. A successful
restart must advance the count exactly once and change PID. The registration
receipt binds generation/bundle/PID and is created by the settings factory only.
PM2 `online` alone does not prove registration: the installer waits up to30seconds
on a monotonic clock for that same PID/count and exact receipt, without another
restart. Every poll bounds PM2 inspection by the remaining wait budget. Timeout,
wrong receipt or process drift preserves `RESTART_INTENT` and the lease.
It proves factory configuration, not direct introspection of the Node-RED global
context or successful delivery of a business response. Synthetic self-tests use
an in-memory sink, never fake409 events in production logs.

If a correct receipt arrives late, the approved operator can forward-resume
without another restart:

```sh
PADLHUB_SUBSCRIPTION409_INSTALL=CONFIRM_147 node /private/packet/installer.cjs resume /private/packet <contract-sha256>
```

`resume` rechecks pinned sources/process/receipt and starts a fresh15minute soak;
it never calls PM2 restart. If the original restart return was not durable (a
timeout/crash), it additionally requires the same explicit quiesced recovery
PID/count/status assertion used below. Forward resume never accepts an offline
process or resumes a pending rollback.

`SOAKING` retains the lease for15minutes. Check exact settings/artifact/flow/helper
hashes, process identity, safe startup/exception aggregates, resource and log
volume, suppression accounting and natural traffic. Make no test booking,
cancellation, payment, DB/provider readback or external message. If there is no
natural409, technical readiness can be recorded separately while reason-path
acceptance remains `PENDING_NATURAL_409`. Do not infer historical causes or equate
finalizer events with HTTP delivery/unique request counts.

`finish` verifies the same process and registration again, writes/fsyncs a finish
receipt before owned lease release and fsyncs the directory. Recovery is
idempotent on either side of unlink and never releases a later foreign lease.

## Rollback and ambiguous restart recovery

```sh
PADLHUB_SUBSCRIPTION409_INSTALL=CONFIRM_147 node /private/packet/installer.cjs rollback /private/packet <contract-sha256>
```

Before restart, exact baseline restoration needs no restart if the original
process is still proven active. After candidate startup, restoring source alone
is insufficient: the guarded baseline restart must finish. Rollback also works
after successful `finish`: it writes a durable deactivation intent and reacquires
the shared lease only against the exact installed source/artifact/process, with
no foreign lease. Pending deactivation prevents an old INSTALLED receipt from
being mistaken for a completed apply/finish.

If restart outcome is unknown, default rollback refuses. After separately
establishing that the previous PM2 command is quiescent and the approved recovery
PID/count is stable, the operator may use the exact recovery identity:

```sh
PADLHUB_SUBSCRIPTION409_INSTALL=CONFIRM_147 node /private/packet/installer.cjs rollback /private/packet <contract-sha256> --restart-quiesced --recovery-pid=<pid> --recovery-count=<count>
```

This is an explicit recovery assertion, never an automatic retry. A returned
baseline restart can be acknowledged without issuing another one. Settings,
flow, helper, machine, process, backup or lease drift fails closed; do not
overwrite foreign state, advance queues/ACKs or remove the durable block. Stop
and coordinate source repair with the owner. Baseline receipt/lease release
requires the baseline settings digest; reappearing candidate source cannot be
reported as ROLLED_BACK.

A settled failed startup can have PID0 with status `errored` or `stopped`. Bind
that exact snapshot with `--recovery-status=errored` (or `stopped`) as well as
PID/count/quiescence. It is never reported as verified online. A guarded baseline
restart is allowed only through that explicit recovery; further failures retain
the lease and require another independently settled recovery decision.

Stop signals: PII/raw fields, initialization failure, new exceptions, uncontrolled
log/resource growth, lost coordination or source/process drift. Restore only the
owned diagnostic settings; preserve immutable artifacts/backups/evidence. Source
rollback does not undo bookings or visit/debit/provider state.

## Rehearsal evidence and limits

```sh
node --test scripts/tests/subscription409Installer.test.mjs scripts/tests/reviewedFlowDeploy.test.mjs
```

All filesystem publication/recovery tests use scratch directories and fake PM2.
Coverage includes SIGKILL at lease link/settings rename, fsync failure, crashes
before/after restart acknowledgement, interrupted rollback/finish, delayed
deactivation, registration failure, missing/corrupt artifacts, foreign drift,
unsafe paths/modes, idempotence and preservation of foreign lease aliases across
all flow/editor entrypoints. Kernel flock uses a real Linux scratch lock in CI;
it is skipped on macOS. These tests perform no live restart, deploy or business
operation. Production activation and natural-traffic acceptance remain separate.
