# PR363: one-node native activation on147

This scoped operation activates the already reviewed empty-tariff diagnostics
without a PM2 restart, provider/DB readback, inject, routing change or shared
observer setting. It does not authorize its own merge or live execution. The
owner must authorize the exact147 activation; preparation and execution evidence
remain distinct. No business API is a smoke endpoint for this operation.

The candidate changes only `func` of the existing preview router. The empty
tariff hook is verbatim PR363. Removing the bootstrap prefix and hook restores
the exact installed business function. Whole-source, function, initializer,
finalizer, library list, node count and exact-graph hashes are pinned. Unknown
drift stops preparation. Do not regenerate installed helpers from current main.

The installed cross-day observer remains in its owned VM slot. A lazy wrapper
delegates its previous observations unchanged and disposes both observers via
the unchanged finalizer. Initializer, finalizer and native library imports stay
byte-for-byte unchanged. Bootstrap runs on the first natural preview message,
not by a synthetic business request. A fixed ready/unavailable marker identifies
the released observer bundle. Bootstrap/logging failures preserve business flow.

The new scoped projection uses PR363's bounded response inspection and shared
sanitizer/budget, but not a second generic extraction on a stripped message.
Only a WeakMap keyed by actual HTTP request retains a server-minted UUID; no
raw message/context/identifier is copied. Exact request equality proves its
tenant/exercise components even if the Function VM has no global `URL`.
The hash does not add ingress/terminal middleware or an access-log join.

## Native sequence

1. Use a dedicated, already authenticated editor tab through the verified
   existing `http://127.0.0.1:18801` tunnel. Do not use the user's working tab.
   Evaluate the generated `editor-readback.js` using the editor's existing AJAX
   setup; call `__preview363Readback()`. This issues only native admin GET/flows
   and returns seven safe origin/time/revision/graph facts. The exact native
   snapshot stays private in the reader closure; the editor ordered
   serialization is pinned independently. A dirty editor, stale editor
   revision,401, missing auth, wrong origin or unexpected shape
   stops before any reservation or native attempt. No auth bypass/fallback.
2. `inspect`, then `prepare` with exact source/identity/code hashes, source
   commit and fresh native evidence (at most30seconds old). The controller
   validates and durably backs up source/candidate/plan before reserving.
3. `reserve` with fresh PRE evidence and
   `RESERVE_PREVIEW363_NATIVE_NO_RESTART_147`; save the plan hash. Then `begin`
   with fresh PRE evidence creates the exclusive one-attempt marker and a
   five-minute `source-preserving-v2` seal. Compare the staged browser-guard
   hash, then use `__preview363Readback.install(seal)` from the same reader
   after its latest fresh read. Its captured snapshot must be at most30seconds
   old. Never install a standalone guard without the private native snapshot.
4. In that tab only, mark the editor dirty without editing graph/configuration
   (`RED.nodes.dirty(true)`) and use native **Deploy modified nodes** once.
   The guard permits only the original authenticated XHR with the independently
   pinned editor serialization, original revision and nodes deployment type.
   The forwarded graph comes entirely from the sealed native snapshot, with
   every field and the original node order preserved and only the pinned func
   substituted. Editor-only coordinates and fields dropped by the serializer
   cannot enter or disappear from the forwarded graph. Every other write,
   editor delta, expired/duplicate seal or fetch mutation is rejected.
   It never replaces the HTTP client or copies Authorization/cookie values.
5. After native HTTP200 ACK, obtain safe guard audit and fresh admin readback.
   Because substitution occurs on the wire, the editor can still hold its
   original serialization. `__preview363Readback()` reads the native API again
   without replacing the armed snapshot. `confirm` binds plan/attempt/body/
   revision/identity, editor hash, ordered source/candidate hashes and disk graph,
   writes the ACK receipt, then starts a full900-second soak. Native ACK alone
   is not proof of running code. Observe fixed ready marker and normal logs;
   test nothing through a business endpoint. A namespaced no-throw listener on
   the existing `ajaxSuccess` may record only count/status/time for exact
   same-origin POST `/flows`; never read response, body or auth headers.
6. `finish` requires fresh POST evidence, unchanged identity/revision/disk and
   the full soak. It writes a durable success receipt before releasing only
   its own lease. Close the dedicated tab rather than removing guard markers.

409/timeout/cancellation/unknown ACK: `reconcile` classifies PRE/POST/UNKNOWN but
does not retry or release custody. Exact observed POST can be explicitly adopted
with `ADOPT_OBSERVED_PREVIEW363_POST_NO_REPLAY_147`, the pinned observed revision
and a new full soak; this records observation, never fabricates an HTTP ACK.

## Exact inverse recovery

Before attempt, `abort` is receipt-first and requires exact PRE evidence. After
attempt, the only reviewed rollback is the inverse func-only native operation
from the owned durable source/candidate, with unchanged target identity and
fresh exact candidate graph/revision. It does not restore unrelated fields or
use the ordinary PM2-restarting rollback path.

Use a **fresh dedicated authenticated tab or hard reload** before inverse
arming; the forward tab's guard is intentionally consumed. Never clear its
Symbol/storage marker or reuse its seal. `rollbackReserve` requires
`ROLLBACK_PREVIEW363_NATIVE_SOURCE_NO_RESTART_147`; `rollbackBegin` creates a
different exclusive inverse attempt/seal. Native modified-nodes sends exactly
the original func, with lifecycle and other nodes unchanged. The fresh reader
privately captures the native candidate and independently pins that tab's
editor serialization; arm through its own `install(inverseSeal)`. `rollbackConfirm`
records actual HTTP ACK and starts a full soak. A durable ACK can be safely
reused if lease publication was interrupted. Lost inverse ACK permits only
explicit `rollbackAdopt` with
`ADOPT_OBSERVED_PREVIEW363_SOURCE_NO_REPLAY_147`, exact observed restored source
and pinned new revision; it cannot replay a POST. `rollbackFinish` writes the
receipt and releases own custody only after full soak. Unknown graph/identity,
foreign revision or foreign lease retains custody for owner decision.

## Checks and stop conditions

Unit/VM tests cover exact hook/inverse restoration, whitelist projection,
shadowing, request correlation, missing `URL`, prior observer preservation,
budget/disposal, sink failure, native auth preservation, scope/serialization/
revision negatives, duplicate attempts, cross-kind leases, ACK interruption and
lost inverse ACK recovery. An isolated real Node-RED4.0.9 rehearsal verifies
modified-node forward/inverse activation with unchanged inject/HTTP/DB fixture
instances and zero provider/DB/inject calls. Nothing targets production APIs.

Stop on source/identity/revision drift, foreign lease, unsupported importer,
missing runtime marker, unexpected diagnostic data, loss of cross-day logging,
response/guard drift or new error growth. Preserve receipts and exact backups;
do not widen scope, query provider/DB, restart, normalize foreign deltas or invent
a price. Activation status must distinguish candidate, native ACK, runtime ready,
soak complete and natural empty-tariff audit observed (which may remain absent).
