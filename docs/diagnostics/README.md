## Contract and accounting

Canonical executable allowlist: `src/utils/errorDiagnosticsCore.mjs`. Its generated JSON schema is
`schema.v1.json`; `example.synthetic.jsonl` is generated by `node scripts/diagnostics/example.mjs`
with synthetic inputs and a public **test-only** HMAC key. The companion vendors this same contract
as TypeScript so it can build without an LK checkout or a new runtime dependency.

Every detailed event has schemaVersion, random diagnosticEventId, random requestId, eventKind,
source, routeTemplate, method, stage, stable code, retriable and outcome. Server events have
serverTimeUtc and monotonic durationMs; browser events have untrusted deviceEventTime and callerBuild.
Missing release/build, reason or outcome is explicitly UNKNOWN/outcome_unknown. Optional unavailable
facts are omitted, never zero. request_terminal is separate from operation_result/DB_ACK and
client_error: disconnect never closes the operation observer or erases a later ACK. A Mongo ACK
proves only the observed local write; matched0 is a refusal. HTTP200/201, payment URLs, OPEN,
VERIFIED, PM2 status, SDK output and persisted LEASED do not establish business success/provider ACL.

IDs are diagnostics, never authorization, idempotency or retry inputs. Browser logicalOperation is
created once per request() invocation (and once for the preview fallback loop); each actual fetch
increments attempt and creates a fresh requestId. Cached/deduped callers may share one actual fetch.
Separate user actions are not deduced from multiple 409s. The response-only X-LK-Request-ID joins a
browser error with a server observation when exposed and fresh; cached response IDs are candidates,
not current-server proof (`serverLinked` requires no-store). No new request header, preflight
requirement, origin, credentials rule, ETag or 304 behavior is introduced. Correlation is absent for
a disconnect before a response; do not manufacture that link. Old clients keep their response body.

MAX uses an ephemeral message context carried through Node-RED message clones; requestId and
attemptReference remain stable inside that send attempt. Distinct leases get distinct attempt
references. Dedicated-key outboxRef/operationRef link attempts and backend persistence; no key means
refs are omitted and refUnavailable=true. leaseAttempt counts lease claims, **not active SDK
executors**. executionObserved=false at prepare/lease; SDK output/exception observations are separate.
Bot route is a logical configuration reference; provider bot identity/access evidence remains false/
unknown. Origin is emitted only from an already available allowlisted origin, otherwise UNKNOWN.
No provider permission check, token comparison or test send is added.

Strict output: fixed keys/enums, boolean flags, bounded numeric counts, validated timestamps, opaque
random IDs and source hashes only; maximum 4096 serialized characters per event. Unknown strings,
objects, URLs/query, request/response bodies, credentials, error.message/stack, claims, session and
business IDs never pass the helper. sourceHash on a hook is explicitly its **uninstrumented business
preimage**, not a claim about installed flow bytes. The future candidate has a separate exact hash.
HMAC refs use a dedicated >=32-byte diagnostic key and domain separation; plain SHA of a phone or
other low-entropy identifier is prohibited. Auth/provider credentials must never be used as this key.
The implementation creates no live secret. Existing non-diagnostic/raw debug outputs are not a safe
sink; deployment must inventory them separately and must not connect new events to raw-message debug.

The shared helper never changes a business return value or invokes another business operation. Hook
calls catch synchronous logging failures; asynchronous sink rejection is counted. Source tests compare
business outputs against the immutable LK base with synthetic inputs. Graph transforms are pure:
exact source/node hashes, route/type/topology checks and conflict checks fail closed before output.
`applySourceHooks` requires the tracked business preimage for 28 hooks, an exact route hash and
same-tab wire reachability (unproven cross-tab links fail closed). Referral prepare/owner use the
current-preimage overlay below instead of replacing a function from tracked source.

## Collector and bounded volume

`createCollector` is a pure versioned parser/checkpoint transition. It does not read an automation,
open a log, start a consumer, or write any state.json. Development tests use only in-memory synthetic
records and disposable state. Keep separate units: canonical_http, auxiliary_nginx, node_red_events,
audit_rows, persisted_client_error, logical_operations, attempts. Never add these into an errors total.
Rows/records, distinct delivered IDs, replayed records, legacy records and late records are separate.
Logical-operation/attempt-context rates require complete observed reference coverage, otherwise they
are null; distinct observed contexts are neither new user actions nor active executors. Device time
does not define a collection window or newness. Each rate carries its actual from/to
window and duration. Unavailable source, invalid window, first nonzero offset without checkpoint,
rotation/truncation/gap => UNKNOWN and rate=null. The caller must verify stat/read inode custody and
window coverage, atomically persist its own checkpoint, and flag loss/late arrival. This parser does
not claim that external custody. A valid first offset0 is only source-start evidence.

Dedupe defaults: at most 10,000 source+event IDs for 24h, with explicit evictions. Restart with the
saved checkpoint preserves the bounded window; losing it cannot establish zero/recovery. No index,
collection migration, monitor-state write, second consumer or exactly-once claim is needed. Client
legacy migration retains original untrusted timestamp and a stable ID in storage or a bounded
in-memory map when writes fail; process restart with failed storage remains an honest dedupe gap.
Browser detail budget is120/minute with one aggregate per second; transport is independently capped
at180 diagnostic fetch attempts/minute, including pending replays and endpoint fallbacks. Deferred
deliveries retain the existing serialized ID and use the existing pending queue. deferredDeliveries
counts blocked delivery attempts, not new errors. queueEvictions counts normal queue-write trimming
only; it does not count all malformed/oversize or previously over-cap legacy records, nor prove durable
loss when browser storage fails. The existing pending limit100 can lose offline records; persisted
records therefore do not measure all device errors.

Server and support helper detail budget: default600/minute per process, <=6000 permitted. Excess
observations update exact in-process observed/suppressed counters; at most one aggregate per event
kind is flushed per second, with no request/entity detail. The aggregate has eventKind=suppression,
aggregate=true, suppressedEventKind and suppressedCount; its requestId is omitted because it is not
a request. Explicit flush/dispose handles shutdown tests; an abrupt process loss can lose the final
in-memory interval. No business retry occurs. Max burst bound: 600 detailed + 360 aggregate records
per minute per helper, each <=4096 characters; provision for roughly 4MiB/minute at the upper bound.
Do not treat suppressed detail as an absent error. Sink delivery itself remains best effort.

Future retention proposal: dedicated restricted-access JSONL stream, rotate at32MiB, cap128MiB per
source and maximum24h, whichever expires first. No raw private exports in a PR. Monitor disk/sink
pressure, observed/suppressed/loggerFailures, cursor gaps and dedupe evictions separately; if capture
fails, mark UNKNOWN. Do not widen logging volume or replay business calls to fill a gap. Retention
and sink provisioning require the separately authorized rollout; no production setting was changed.
