# Оплата событий по подписке

При присоединении к групповой тренировке Viva вернула SERVICE стоимостью
550 000 копеек, но установленный обработчик передал его в сериализатор открытых
игр, требующий номинал 1 000 000 копеек. Запись уже существовала, а создание
транзакции ещё не начиналось. Новый код разделяет эти пути.

| Событие | Серверное действие | Услуга | Правило скидки | Посещения |
| --- | --- | --- | --- | --- |
| Открытая игра | JOIN_GAME / CREATE_GAME | Существующий SERVICE 10 000 ₽ | gameOverageDiscountPercent и бесплатные минуты | По правилам игры |
| Групповая тренировка | BOOK_GROUP_TRAINING | Разовая услуга конкретного упражнения | groupTrainingDiscountPercent | 0 |
| Турнир | BOOK_TOURNAMENT | Разовая услуга конкретного упражнения | tournamentDiscountPercent | 0 |

При цене 5 500 ₽ и групповом правиле 50% к оплате получается 2 750 ₽.
Процент не зафиксирован в обработчике. Используется целочисленный расчёт:
`baseMinor - floor(baseMinor * percent / 100)`.

## Маршрутизация и проверки

Совместимые HTTP точки входа сохраняются:

- `POST /lk/subscriptions/game-price-preview`: новый `targetKind: TOURNAMENT`,
  отдельный `TOURNAMENT_SUBSCRIPTION_DISCOUNT_V1`; группа сохраняет свой kind.
- `POST /lk/subscriptions/book`: `expectedTournamentDiscount` и
  `expectedGroupDiscount` взаимно исключаются и только ограничивают серверный
  расчёт. Тип события заново определяется по Viva.

Внутренние шаги `lk1_group_payment_products/profile` и
`lk1_tournament_payment_products/profile` используют отдельный контекст
`lk1EventPayment`; они не входят в `_splitCtx`. Путь `lk1_payment_products`
принимает только открытые игры. Общими остаются сохранение операции, CAS перед
единственным POST транзакции и проверка результата Viva.

Перед оплатой повторно проверяются владелец профиля, текущие правила,
ID/номинал/тип услуги, станция и ID подтверждённой записи. Все присутствующие
алиасы должны совпадать. Предварительная цена имеет прежние ограничения:
не более 1 000 000 копеек и продолжительность события не более 720 минут.

Viva self-list может не содержать владельца в каждой строке. Подтверждение
разрешено только после конкретного GET собственного списка с тем же токеном,
клиентом, operationId и operationKey, без перенаправлений. Проверяется ровно
одна активная запись нужного упражнения с нужным способом оплаты. Любой явно
указанный другой владелец запрещает подтверждение. Доказательство запроса
расходуется один раз и не записывается в Mongo.

Неоднозначная операция повторно не создаёт запись или счёт. Проверенная старая
ссылка остаётся доступна при повторе; отсутствие проверенного результата
возвращает сверку. Исправление кода не восстанавливает автоматически уже
зависшие пользовательские операции.

## Точечная подготовка Node-RED

`prepare_event_payment_routes_upgrade.mjs` принимает свежий приватный live flow
и создаёт новый приватный каталог с candidate, exact graph contract и summary.
Скрипт сам не подключается к серверу и не выполняет deploy. Он проверяет SHA256
до и после изменения пяти function nodes:

- `lk_subscription_booking_prepare_20260804`
- `lk_subscription_booking_router_20260804`
- `lk_subscription_booking_finalize_20260804`
- `lk_subscription_price_preview_20260908_entry`
- `lk_subscription_price_preview_20260908_router`

Меняются только `func`; ID, wires, настройки HTTP/Mongo, split function и все
остальные узлы сохраняются. Установленная логика создания и списания посещений
открытых игр сохраняется; исправляется подтверждение владельца. Артефакт не
переносит остальные изменения main на сервер. Старый group-only пакет #64
остаётся с прежними pins и намеренно отклоняет изменившийся canonical source.

```bash
node scripts/prepare_event_payment_routes_upgrade.mjs \
  /absolute/private/source.flow.json \
  /absolute/new-private-output event-payment-routes
```

Повторное применение, изменение исходных function bodies, лишние узлы и
несовпадение postimage блокируются. Перед выпуском нужны свежая сверка live
preimage, стандартный reviewed-flow preflight/rollback, разрешение на deploy
и проверка обоих событий. Frontend выпускается после совместимого backend.
Полная сборка с `ci.invalid` предназначена только для проверки компиляции.

## Проверки

- `groupEventPayment.test.mjs`: услуга события, группы/турниры, правила
  0/20/33/50/100%, запрет подмены тарифа и категории, CAS, повтор операции.
- `eventPaymentReadback.test.mjs`: привязка self-list к запросу и владельцу.
- `eventPaymentRoutesUpgrade.test.mjs`: точный состав изменений, дрейф,
  повторное применение, несовпадение postimage и приватный output.
- `tournamentSubscriptionDiscount.test.ts` и
  `tournamentSignup.checkoutReadiness.test.ts`: цена, контекст аккаунта/события,
  конфликт quote kinds, ошибки/ручной повтор без цикла запросов.
- `eventPaymentLiveComposition.test.mjs`: полный установленный gateway после
  точечного patch исполняется с синтетическими сообщениями без HTTP/Mongo.
  Требует `LK_EVENT_ROUTES_LIVE_FIXTURE`; приватный flow не хранится в Git/CI.

На свежем flow от 14 сентября локально проверены все пять pre/postimage,
неизменность остальных узлов, подтверждение открытой игры без owner fields,
отказ при другом владельце/отсутствии proof и выбор услуг группы/турнира.
Это локальное доказательство; реальный платёж и deploy не выполнялись.
