# Персональные данные и логирование

## Какие данные вы передаёте

| Поле | Тип | Комментарий |
| --- | --- | --- |
| `externalPlayerId` | Псевдонимный идентификатор | Стабильный ID игрока на вашей стороне |
| `displayName` | Отображаемое имя | Показывается в составе игры |
| `payment.reference` | Идентификатор расчёта | Внешняя ссылка, не платёжные реквизиты |
| `payment.paidAt` | Время | UTC ISO |
| `payment.amountMinor`, `payment.currency` | Сумма | Минимальные единицы + ISO-код валюты |

**Не требуются и не принимаются:** телефон, e-mail, паспортные данные, номера карт,
платёжные реквизиты, произвольный PadlHub user ID, массив участников, Viva client или
booking ID.

## Что хранит PadlHub

- канонический membership (`membershipId`, `gameId`, `externalPlayerId`,
  `payment.reference`, состояние);
- проекцию оплаты `PAID` с источником `EXTERNAL_PARTNER` в записи игры;
- audit-записи операций (коды, correlation, идентификаторы) для расследования и
  reconciliation;
- outbox-события для внутренней обработки.

## Логирование

Никогда не логируются: подпись, HMAC-секрет, сырой nonce, сырой IP, полное тело,
`displayName`, `payment.reference`. Nonce, IP и тело представлены
HMAC-отпечатками с отдельным audit-ключом. Access-логи редактируются, тело запроса не
пишется, security-заголовки не пишутся.

Вам рекомендуется то же правило: логировать `operationId`, `correlationId`,
HTTP-статус, код ошибки и латентность; не логировать секреты и персональные данные.

## Хранение и удаление

- `DELETE` удаляет membership и снимает проекцию из состава игры.
- Audit- и operation-записи **не удаляются** удалением участника: они нужны для
  расследования и reconciliation. Это не пользовательский контент, а журнал операций.
- **Срок хранения — один год.** Завершённые membership и audit-записи удаляются
  ежемесячной регламентной задачей с отчётом после 365 дней с момента записи.
  Завершённые операции (`COMPLETED`, `FAILED`) хранятся минимум 365 дней после
  последнего обновления; после удаления операции повтор её idempotency key больше
  не возвращает сохранённый результат. Активные membership и незавершённые операции,
  включая `UNKNOWN`, сохраняются до завершения reconciliation и не удаляются по возрасту.
- Nonce-записи удаляются автоматически по TTL (24 часа) и в годовом хранении не
  участвуют.
- Доступ к audit — отдельная read-only роль; выгрузка в SIEM согласуется отдельно.

## Ответственность сторон

- **Вы:** защита секретов и сертификатов, разделение окружений, отсутствие
  персональных данных в логах, корректная обработка кодов ошибок.
- **PadlHub:** серверная безопасность, аудит, сохранность данных, корректность
  взаимодействия с Viva, управляемое отключение и восстановление.
