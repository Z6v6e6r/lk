# Лимиты, таймауты и сеть

Значения ниже — действующие лимиты пилота. Они проверяются ingress и сервером;
вы должны закладывать их в свой клиент (backoff, размеры, конкурентность).

## Тело и заголовки

| Параметр | Значение |
| --- | --- |
| `Content-Type` | только `application/json`, без `charset` |
| Максимальный размер тела | 16 384 байта |
| Максимальный размер строки запроса | 2 048 байт |
| Максимальный размер заголовков | 16 384 байта |
| Дубли critical-заголовков | отклоняются |
| Дубли ключей в JSON | отклоняются |
| Chunked transfer / content encoding | не поддерживаются |

Critical-заголовки (каждый ровно один раз):
`content-type`, `x-padlhub-client-id`, `x-padlhub-audience`, `x-padlhub-key-id`,
`x-padlhub-timestamp`, `x-padlhub-nonce`, `idempotency-key`, `x-correlation-id`,
`x-padlhub-signature`.

Path сохраняется без нормализации; каноническая семантика JSON — как в
[SIGNING.md](SIGNING.md).

## Rate limit и конкурентность

| Параметр | Значение |
| --- | --- |
| Запросов в секунду на клиента | 2, burst 10 |
| Запросов в секунду на источник | 5, burst 20 |
| Одновременных запросов на клиента | 4 |
| Одновременных запросов на источник | 8 |
| Таймаут upstream | 15 секунд |

Превышение даёт `429`. Учитывайте `Retry-After`, если он присутствует; иначе
используйте экспоненциальный backoff с джиттером. Не ретраить на уровне «просто
повторим запрос» — см. [IDEMPOTENCY.md](IDEMPOTENCY.md).

## Таймауты и неоднозначный результат

Наш ответ ограничен по времени (15 с). Если ответ не получен или соединение
оборвалось (`408`, `502`, `504`), результат операции **неизвестен**: читайте операцию
через `GET`. Не выполняйте слепой повтор мутации.

## Транспорт

| Параметр | Значение |
| --- | --- |
| Минимальная версия TLS | 1.2 |
| Идентификация клиента | mTLS (обязательно) |
| CIDR как единственная идентичность | запрещён |
| Адрес прослушивания sidecar | только loopback (внутренний контур) |
| `Cache-Control` в ответах | `no-store` |
| CORS-заголовки | скрываются |

Dedicated ingress принимает только точный Host/SNI и три маршрута, стирает входные
`Forwarded`/`X-Forwarded-*` и формирует их из socket peer. Node-RED недоступен
напрямую.

## Наблюдаемость на вашей стороне

Рекомендуем логировать `operationId`, `correlationId`, HTTP-статус, код ошибки и
латентность. **Не** логируйте подпись, секрет, nonce, полное тело, `displayName` или
`payment.reference`. Детали: [DATA_PROTECTION.md](DATA_PROTECTION.md).
