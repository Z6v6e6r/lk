# PadlHub: подписки в Zero Block, версия 2

Дизайнер рисует карточки в Tilda. Скрипт подставляет цены и остатки, а кнопка открывает окно оформления поверх той же страницы. Переход на sub_hab и повторный выбор тарифа больше не нужны.

**Для запуска требуется публикация обновлённого subscription-storefront.js с checkoutVersion=1 и checkoutChannel.** Этот комплект содержит новый код, а не подтверждение его публикации. Если на сервере старая версия, кнопки заблокируются с сообщением о необходимости обновления. Дизайнер не должен обходить эту проверку или менять endpoint оплаты.

## Подключение в Tilda

1. Нарисуйте карточки в Zero Block. Цену, период, остаток, статус и кнопку создайте отдельными элементами.
2. В настройках элементов задайте CSS-классы из таблицы ниже **без точки**.
3. Кнопке назначьте ссылку `#`. Не подключайте к ней корзину, форму, другой popup или дополнительный обработчик оплаты.
4. Удалите прежнюю вставку версии 1 и код, который рисовал всю витрину `padlhub-subscriptions`. Должна остаться только одна новая вставка.
5. Добавьте T123 **после всех Zero Block**, которые нужно подключить.
6. Вставьте всё содержимое одного файла: `T123-обычные.html` или `T123-Питер.html`. JS уже внутри. Эти файлы генерируются командой ниже и включаются в ZIP для дизайнера.
7. Опубликуйте страницу и проверьте её публичный URL на телефоне и компьютере. Редактор Tilda не заменяет такую проверку.

Сам скрипт карточки не рисует. Высота артборда, цвета, шрифты, изображения, подписи периода и адаптивы остаются у дизайнера. Модальное окно входа и оформления предоставляет PadlHub.

## Классы

Вместо `<ключ>` подставьте ключ предложения из следующей таблицы.

| Элемент | Класс | Пример |
|---|---|---|
| Цена со знаком ₽ | `ph-price-<ключ>` | `ph-price-friendship` |
| Число доступного остатка | `ph-remaining-<ключ>` | `ph-remaining-friendship` |
| Число общего лимита | `ph-total-<ключ>` | `ph-total-friendship` |
| Статус загрузки, ошибки или недоступности | `ph-status-<ключ>` | `ph-status-friendship` |
| Кнопка оформления | `ph-buy-<ключ>` | `ph-buy-friendship` |
| Вся строка счётчика, необязательно | `ph-counter-<ключ>` | `ph-counter-friendship` |
| Контейнер карточки, необязательно | `ph-card-<ключ>` | `ph-card-friendship` |

Текст внутри `.tn-atom` у отмеченного элемента заменяется целиком. Не помещайте туда иконки, другой текст или второй знак ₽. Начальная цена и числа — `—`. Для статуса оставьте две-три строки на мобильном адаптиве.

Если элементы дублированы на разных разрешениях, назначьте класс каждому соответствующему экземпляру. Если Tilda-группа не создаёт общий DOM-контейнер, назначьте `ph-counter-<ключ>` всем элементам строки «Осталось X / Y». Тогда вся строка скроется при безлимите. Скрытие элементов не меняет автоматически высоту Zero Block.

## Ключи предложений

| Ключ | Предложение | Период | Источник цены/счётчика |
|---|---|---|---|
| `friendship` | Дружба | 30 дней | API, счётчик friendship |
| `friendship-year` | Дружба, год | год | API, отдельный счётчик network_friendship |
| `academy` | Академия | 30 дней | API, academy |
| `ra` | РА | 30 дней | API, ra |
| `energy5` | Энергия 5 | 60 дней, 5 занятий | API, energy5 |
| `atlanty` | ДРУЖБА.АТЛАНТЫ | 30 дней | каталог клуба, 6 800 ₽ (прежняя 9 800 ₽) |
| `friendship-promo` | Дружба, акция Питера | 30 дней | каталог акции, 4 900 ₽ |
| `academy-promo` | Академия, акция Питера | 30 дней | каталог акции, 11 900 ₽ |
| `ra-promo` | РА, акция Питера | 30 дней | каталог акции, 11 900 ₽ |

Акционные цены статические; их нужно обновлять вместе с каталогом при изменении акции. Это не персональный расчёт CRM. Счётчики обычных подписок не используются для акций. Применимость предложения проверяется при оформлении. Для годовой Дружбы нельзя подставлять месячный остаток.

`atlanty` — прямой продукт Viva без счётчика: цена тоже статическая (каталог клуба), из status API не читается, а пустой product id закрывает оформление. Годовой клубный вариант (`atlanty-year`) появится вместе с его product id.

## Настройка вставки

В конце T123 находится:

```js
window.phSubscriptions = window.PadlHubZeroBlock.init({
  offerKeys: ['friendship', 'academy', 'ra'],
  channel: 'prod',
  refreshMs: 30000
});
```

Для Питера замените список на `['friendship-promo', 'academy-promo', 'ra-promo']`. Для смешанной страницы перечислите нужные ключи в одном списке. Не вставляйте оба файла T123 одновременно.

Необязательное `root: '#rec123456789'` ограничивает поиск одним блоком с таким ID. Без root скрипт ищет элементы по всей странице. Повторный init на том же root запрещён. По умолчанию нужен один вызов init на всю страницу.

`channel: 'dev'` предназначен для отдельной тестовой страницы. Нельзя смешивать PROD и DEV или подключать старый виджет рядом: скрипт проверяет канал модуля и при несовпадении блокирует оформление. Не выбирайте канал из параметров ссылки посетителя.

## Как проходят вход и оплата

1. Посетитель нажимает кнопку конкретной карточки. Открывается модальное окно с выбранными подпиской, периодом и ценой.
2. Скрипт проверяет текущую сессию. Если входа нет, показывает существующую форму PadlHub с обязательными согласиями и подтверждением телефона.
3. Вход по SMS происходит в модальном окне. Вход через VK/Яндекс использует существующий переход к провайдеру авторизации и обратно; полное отсутствие внешних переходов для OAuth не обещается. Выбор сохраняется на 30 минут в этой вкладке, после возвращения окно может открыться повторно.
4. После входа посетитель **сам нажимает «Перейти к оплате»**. Завершение входа не создаёт покупку автоматически.
5. Для годовой Дружбы дополнительно требуется отдельное, изначально снятое согласие с условиями годовой подписки. Сами условия и публичная оферта должны быть доступны посетителю на лендинге.
6. Скрипт загружает телефон из профиля и повторно проверяет доступность и цену. При изменении цены просит обновить данные и подтвердить её заново.
7. Существующий серверный API создаёт покупку и возвращает банковскую ссылку. Скрипт переходит на защищённую страницу банка. Банковские реквизиты в Zero Block не вводятся.
8. Банк возвращает посетителя на этот же лендинг. Окно восстанавливается без повторного создания покупки.

Сам переход обратно не подтверждает оплату. Для Дружбы и годовой Дружбы доступна кнопка «Проверить статус оплаты» — проверяется только ранее сохранённая попытка. Для прямых продуктов (Академия, РА, Энергия 5) и акций API не предоставляет этому модулю отдельный confirm-контракт: результат предлагается проверить в личном кабинете.

## Ошибки и повторное оформление

- Во время загрузки модуля и при ошибке счётчика кнопка карточки недоступна. Последние известные значения могут остаться видимыми, но не разрешают покупку.
- При безлимите строка остатка скрывается. Ошибка загрузки не превращается в «Осталось 0».
- Одновременные клики и вкладки защищены блокировкой браузера. Перед отправкой покупки сохраняется отметка попытки; автоматических повторных POST нет.
- При таймауте, пустом ответе, перезагрузке или возвращении из банка отметка остаётся. В этой версии она сохраняется и после подтверждения оплаты: повторное оформление этого предложения в том же браузере требует проверки поддержкой. Смена аккаунта не очищает отметку.
- Дизайнеру нельзя удалять эту отметку для «починки кнопки». Неясный результат сначала сверяется с CRM/платежом. Очистка отметки без сверки может привести к второй покупке.
- Подготовка профиля ограничена 12 секундами, ожидание операции — 20 секундами. После таймаута окно снова можно закрыть; поздний ответ не вызывает неожиданный переход. Неопределённый отправленный платёж остаётся защищённым.
- Для оформления нужны HTTPS, современный Safari/Chrome с Web Locks и доступное хранилище сайта. При отсутствии этих возможностей покупка блокируется с объяснением.

В новом хранилище только ключ предложения, идентификатор попытки и её состояние. Новый скрипт не передаёт дизайнеру телефон, токен или банковскую ссылку. Вход и платёжные API принадлежат существующему модулю PadlHub.

## Для разработчика

```js
await window.phSubscriptions.refresh();
window.phSubscriptions.getState('friendship');
// { status, data, checkoutReady, checkoutError }

window.phSubscriptions.destroy();
// true: обработчики сняты, исходные тексты и атрибуты восстановлены.
// false: оформление сейчас обрабатывает запрос; дождитесь результата и повторите destroy.
```

Событие `padlhub:subscription` на root содержит только публичные данные карточки: `event.detail.key`, `event.detail.state`. Это не событие оплаты.

Модуль витрины после загрузки также предоставляет:

```js
window.LKWidgetSubscriptionStorefront.openCheckout('friendship-year');
window.LKWidgetSubscriptionStorefront.openCheckout('atlanty'); // ДРУЖБА.АТЛАНТЫ, 6 800 ₽
window.LKWidgetSubscriptionStorefront.closeCheckout();
window.LKWidgetSubscriptionStorefront.resumeCheckout();
```

`openCheckout` только открывает интерфейс. Он не принимает произвольный productId, цену, телефон, токен или банковскую ссылку. Одновременно открыто одно окно. `closeCheckout` возвращает false во время обработки операции. Не вызывайте `mount()` для дизайнерского блока — это метод полной витрины.

## Приёмка на опубликованной странице

- Загружаются правильные цены и отдельный годовой счётчик; все мобильные дубли размечены.
- Кнопка каждого предложения открывает его точное название и период без перехода на sub_hab.
- При отсутствии сессии доступна форма входа; после входа ожидается явное подтверждение оплаты.
- Годовой тариф нельзя оформить без отдельного согласия.
- Нулевой остаток, неполный ответ или ошибка API блокируют оформление.
- Модальное окно помещается на телефоне, прокручивается, удерживает фокус; Escape и крестик закрывают его вне обработки запроса.
- После закрытия фокус возвращается к кнопке карточки.
- Возврат из банка не создаёт вторую покупку и не объявляет успех по URL.
- На странице нет второй старой вставки, DEV-модуля рядом с PROD или стороннего обработчика на тех же кнопках.

## Подготовка комплекта и локальная проверка

Для разработчика проекта:

```sh
npm run build:subscription-storefront
npm run build:subscription-storefront:dev
node scripts/package-zero-block.mjs /private/tmp/padlhub-zero-block-v2
node scripts/preview-zero-block.mjs
node --experimental-strip-types --test scripts/tests/subscriptionStorefrontPromo.test.ts scripts/tests/subscriptionStorefront.test.ts
```

Локальный preview на 127.0.0.1:5197 перехватывает все fetch-запросы и использует синтетические вход/платежи. Он проверяет интерфейс, а не подтверждает работоспособность живого эквайринга. Примеры query: `auth=0`, `auth=1`, `fail=timeout`, `fail=status`, `paid=1`.

Владелец: PadlHub. Аудитория: посетители Tilda-лендингов. Ожидаемый результат: выбранная карточка открывает вход и оформление на той же странице. Сигнал остановки: неверный тариф/цена, смешение каналов, повторный POST или непроверенный результат. Способ остановки: убрать новую вставку T123 с лендинга; это останавливает новые открытия, но не отменяет уже отправленные покупки.
