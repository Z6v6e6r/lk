# PadlHub: подписки в Zero Block, версия 2

Дизайнер рисует карточки в Tilda. Скрипт подставляет цены и остатки, а кнопка открывает окно оформления поверх той же страницы. Переход на sub_hab и повторный выбор тарифа больше не нужны.

**Для запуска требуется публикация обновлённого subscription-storefront.js с checkoutVersion=1 и checkoutChannel.** Этот комплект содержит новый код, а не подтверждение его публикации. Если на сервере старая версия, кнопки заблокируются с сообщением о необходимости обновления. Дизайнер не должен обходить эту проверку или менять endpoint оплаты.

## Подключение в Tilda

1. Нарисуйте карточки в Zero Block. Цену, период, остаток, статус и кнопку создайте отдельными элементами.
2. В настройках элементов задайте CSS-классы из таблицы ниже **без точки**.
3. Кнопке назначьте ссылку `#`. Не подключайте к ней корзину, форму, другой popup или дополнительный обработчик оплаты.
4. Удалите прежнюю вставку версии 1 и код, который рисовал всю витрину `padlhub-subscriptions`. Должна остаться только одна новая вставка.
5. Добавьте T123 **после всех Zero Block**, которые нужно подключить.
6. Вставьте всё содержимое одного файла: `T123-обычные.html` или `T123-Питер.html`. JS уже внутри. Эти файлы генерируются командой ниже и включаются в ZIP для дизайнера.
7. Опубликуйте страницу и проверьте её публичный URL на телефоне и компьютере. Редактор Tilda не заменяет такую проверку.

Сам скрипт карточки не рисует. Высота артборда, цвета, шрифты, изображения, подписи периода и адаптивы остаются у дизайнера. Модальное окно входа и оформления предоставляет PadlHub.

### Главная padlhub.ru: «Играй выгодно»

Для главной используйте один `T123-Главная.html` после карточек. Он обслуживает только `#rec4807682401`; при смене ID нужно обновить bootstrap. Кнопки сохраняют существующие классы `ph-buy-friendship`, `ph-buy-ra`, `ph-buy-academy`, `ph-buy-energy5` и настоящую ссылку **`https://padlhub.ru/sub_hab`**. Не заменяйте её на `#`: без JS или при отключении вставки должен открываться рабочий каталог.

**Новый bootstrap требует adapter 2.1.0/2.2.0/2.3.0 и опубликованный runtime с `checkoutIsolationVersion=1`, `checkoutVersion=1`, `checkoutChannel=prod`, `isCheckoutOpen()`.** Прежний runtime не разрешается открывать поверх главной: по клику посетитель уйдёт в каталог. Публикация кода и вставки — отдельные шаги; локальные тесты не подтверждают live-активацию.

Сначала опубликуйте новую пару `subscription-storefront.js` + `release.json`, собранную `npm run build:subscription-storefront`. Манифест дополнительно содержит версии checkout, канал и `script: { fileName, integrity }`. Вставка проверяет этот контракт **до выполнения JS**, а браузер проверяет SHA-384 файла через SRI (`crossorigin=anonymous`). Старый манифест, несогласованная пара файлов, ошибка CORS или несовпадение хеша дают резервный переход. Не дописывайте capability/хеш вручную к старому релизу. DEV собирается той же командой с суффиксом `:dev` и отдельной парой файлов.

Удалите старый скрипт переключения месяца/года с `PadlHubZeroBlock.checkoutUrl()`. Не оставляйте вторую инициализацию T123. Новый скрипт обслуживает `.ph-period-month`, `.ph-period-year`, `.ph-period-label` и все адаптивные дубли Дружбы. Год использует отдельный `network_friendship`; `.count-box.is-hidden` сохраняет скрытие месячной строки для года.

При исправной вставке эти адреса открывают выбранное оформление поверх главной:

| Предложение | Адрес |
|---|---|
| Дружба, месяц | `https://padlhub.ru/#ph-checkout=friendship` |
| Дружба, год | `https://padlhub.ru/#ph-checkout=friendship-year` |
| РА | `https://padlhub.ru/#ph-checkout=ra` |
| Академия | `https://padlhub.ru/#ph-checkout=academy` |
| Энергия 5 | `https://padlhub.ru/#ph-checkout=energy5` |

Это ссылки выбора интерфейса, не персональные банковские URL. Их можно использовать для переходов из других разделов. На самих кнопках главной оставляйте реальную резервную ссылку и класс конкретного предложения: скрипт перехватывает обычный клик. Ctrl/Meta/Shift и средняя кнопка мыши сохраняют нативный переход в каталог. Список ключей жёстко задан; параметры `offer`, `productId`, `price`, `channel` посетителя не меняют обычные продукты или PROD-канал. Акции Петербурга `*-promo` — другие продукты.

#### Защита главной

- До открытия секции подписок/явной ссылки или восстановления входа нет сетевых запросов вставки. При видимой секции загружаются только цены/остатки. Тяжёлый runtime и его CSS запрашиваются по клику оформления или при валидном восстановлении UI после банка/OAuth.
- Если IntersectionObserver недоступен, фонового обновления нет; выбранный тариф проверяется по клику и при оформлении. Polling останавливается вне секции и в скрытой вкладке; после ошибок интервал растёт до пяти минут. Подтверждение покупки всё равно заново проверяет цену и доступность.
- На загрузку UI отведено 12 секунд. Ошибка загрузки, неподходящая версия или канал дают один резервный переход в `/sub_hab`. Это происходит до передачи управления checkout. При существующей отметке предыдущей попытки или недоступном хранилище автоматический резервный переход запрещён, даже после закрытия окна; восстановление остаётся доступным и при нулевом остатке. Ошибки входа/оплаты не запускают резервный переход и повторный POST.
- Двойные клики объединяются. Escape, скрытие вкладки и `destroy()` отменяют ожидающее открытие; поздняя загрузка не открывает окно и не перенаправляет посетителя. Во время отправленного платежа destroy отказывается снимать checkout.
- Zero checkout использует те же Viva/legacy auth providers, не устанавливая глобальные LK error/click/idle hooks и не подменяя fetch/XHR/beacon/WebSocket. Обычная телеметрия входа, обработка согласий и сессии сохраняются. Уже установленная защита другого LK-виджета не удаляется.
- Переменные темы и auth CSS ограничены контейнерами runtime/checkout; шрифт формы имеет собственный alias. Полная витрина, промокодный portal и её собственный idle guard сохраняют стили. CSS вставки ограничен `data-ph-zero-root`.
- Быстрое отключение: перед bootstrap установить `window.PADLHUB_MAIN_CHECKOUT_DISABLED = true` или убрать новую T123. Настоящие ссылки каталога останутся. Это не отменяет уже отправленные покупки и не очищает attempt markers.

Перед публикацией: сравнить главную до/после, внешние формы/кнопки и CSS variables, проверить desktop/mobile, имитировать timeout/ошибку модуля, банк/OAuth возврат без новой покупки и нулевую загрузку runtime до intent. Влияние на конверсию требует реальных метрик; отсутствие регрессии по одному code review не обещается. Откат: убрать новую T123 и восстановить сохранённый старый обработчик периода. Реальные платежи для локальной проверки не нужны.

## Классы

Вместо `<ключ>` подставьте ключ предложения из следующей таблицы.

| Элемент | Класс | Пример |
|---|---|---|
| Цена со знаком ₽ | `ph-price-<ключ>` | `ph-price-friendship` |
| Число доступного остатка | `ph-remaining-<ключ>` | `ph-remaining-friendship` |
| Число общего лимита | `ph-total-<ключ>` | `ph-total-friendship` |
| Статус загрузки, ошибки или недоступности | `ph-status-<ключ>` | `ph-status-friendship` |
| Кнопка оформления | `ph-buy-<ключ>` | `ph-buy-friendship` |
| Вся строка счётчика, необязательно | `ph-counter-<ключ>` | `ph-counter-friendship` |
| Контейнер карточки, необязательно | `ph-card-<ключ>` | `ph-card-friendship` |

Текст внутри `.tn-atom` у отмеченного элемента заменяется целиком. Не помещайте туда иконки, другой текст или второй знак ₽. Начальная цена и числа — `—`. Для статуса оставьте две-три строки на мобильном адаптиве.

Если элементы дублированы на разных разрешениях, назначьте класс каждому соответствующему экземпляру. Если Tilda-группа не создаёт общий DOM-контейнер, назначьте `ph-counter-<ключ>` всем элементам строки «Осталось X / Y». Тогда вся строка скроется при безлимите. Скрытие элементов не меняет автоматически высоту Zero Block.

| `friendship-year` | Дружба, год | год | API, отдельный счётчик network_friendship |
| `academy` | Академия | 30 дней | API, academy |
| `ra` | РА | 30 дней | API, ra |
| `energy5` | Энергия 5 | 60 дней, 5 занятий | API, energy5 |
| `atlanty` | ДРУЖБА.АТЛАНТЫ | 30 дней | каталог клуба, 6 800 ₽ (прежняя 9 800 ₽) |
| `topocraty` | ДРУЖБА.ТОПОКРАТЫ | 30 дней | каталог клуба, 6 800 ₽ (прежняя 9 800 ₽) |
| `friendship-promo` | Дружба, акция Питера | 30 дней | каталог акции, 4 900 ₽ |
| `academy-promo` | Академия, акция Питера | 30 дней | каталог акции, 11 900 ₽ |
| `ra-promo` | РА, акция Питера | 30 дней | каталог акции, 11 900 ₽ |

Акционные цены статические; их нужно обновлять вместе с каталогом при изменении акции. Это не персональный расчёт CRM. Счётчики обычных подписок не используются для акций. Применимость предложения проверяется при оформлении. Для годовой Дружбы нельзя подставлять месячный остаток.

`atlanty` — прямой продукт Viva без счётчика: цена тоже статическая (каталог клуба), из status API не читается, а пустой product id закрывает оформление. Годовой клубный вариант (`atlanty-year`) появится вместе с его product id.

`topocraty` — клубная подписка «Дружба Топократы» тем же способом: продаётся id подписки из каталога «Абонементы» (`14692232-12be-4218-9fa1-2d5b79b62035`), цена статическая из каталога витрины, пустой id закрывает оформление. Карточки витрины у ключа нет — он вызывается напрямую `openCheckout('topocraty')` с страницы Топократов.

## Настройка вставки

В конце T123 находится:

```js
window.phSubscriptions = window.PadlHubZeroBlock.init({
  offerKeys: ['friendship', 'academy', 'ra'],
  channel: 'prod',
  refreshMs: 30000
});
```

Для Питера замените список на `['friendship-promo', 'academy-promo', 'ra-promo']`. Для смешанной страницы перечислите нужные ключи в одном списке. Не вставляйте оба файла T123 одновременно.

Необязательное `root: '#rec123456789'` ограничивает поиск одним блоком с таким ID. Без root скрипт ищет элементы по всей странице. Повторный init на том же root запрещён. По умолчанию нужен один вызов init на всю страницу.

`channel: 'dev'` предназначен для отдельной тестовой страницы. Нельзя смешивать PROD и DEV или подключать старый виджет рядом: скрипт проверяет канал модуля и при несовпадении блокирует оформление. Не выбирайте канал из параметров ссылки посетителя.

## Как проходят вход и оплата

1. Посетитель нажимает кнопку конкретной карточки. Открывается модальное окно с выбранными подпиской, периодом и ценой.
2. Скрипт проверяет текущую сессию. Если входа нет, показывает существующую форму PadlHub с обязательными согласиями и подтверждением телефона.
3. Вход по SMS происходит в модальном окне. Вход через VK/Яндекс использует существующий переход к провайдеру авторизации и обратно; полное отсутствие внешних переходов для OAuth не обещается. Выбор сохраняется на 30 минут в этой вкладке, после возвращения окно может открыться повторно.
4. После входа посетитель **сам нажимает «Перейти к оплате»**. Завершение входа не создаёт покупку автоматически.
5. Для годовой Дружбы дополнительно требуется отдельное, изначально снятое согласие с условиями годовой подписки. Сами условия и публичная оферта должны быть доступны посетителю на лендинге.
6. Скрипт загружает телефон из профиля и повторно проверяет доступность и цену. При изменении цены просит обновить данные и подтвердить её заново.
7. Существующий серверный API создаёт покупку и возвращает банковскую ссылку. Скрипт переходит на защищённую страницу банка. Банковские реквизиты в Zero Block не вводятся.
8. Банк возвращает посетителя на этот же лендинг. Окно восстанавливается без повторного создания покупки.

Сам переход обратно не подтверждает оплату. Для Дружбы и годовой Дружбы доступна кнопка «Проверить статус оплаты» — проверяется только ранее сохранённая попытка. Для прямых продуктов (Академия, РА, Энергия 5) и акций API не предоставляет этому модулю отдельный confirm-контракт: результат предлагается проверить в личном кабинете.

## Ошибки и повторное оформление

- Во время загрузки модуля и при ошибке счётчика кнопка карточки недоступна. Последние известные значения могут остаться видимыми, но не разрешают покупку.
- При безлимите строка остатка скрывается. Ошибка загрузки не превращается в «Осталось 0».
- Одновременные клики и вкладки защищены блокировкой браузера. Перед отправкой покупки сохраняется отметка попытки; автоматических повторных POST нет.
- При таймауте, пустом ответе, перезагрузке или возвращении из банка отметка остаётся. В этой версии она сохраняется и после подтверждения оплаты: повторное оформление этого предложения в том же браузере требует проверки поддержкой. Смена аккаунта не очищает отметку.
- Дизайнеру нельзя удалять эту отметку для «починки кнопки». Неясный результат сначала сверяется с CRM/платежом. Очистка отметки без сверки может привести к второй покупке.
- Подготовка профиля ограничена 12 секундами, ожидание операции — 20 секундами. После таймаута окно снова можно закрыть; поздний ответ не вызывает неожиданный переход. Неопределённый отправленный платёж остаётся защищённым.
- Для оформления нужны HTTPS, современный Safari/Chrome с Web Locks и доступное хранилище сайта. При отсутствии этих возможностей покупка блокируется с объяснением.

В новом хранилище только ключ предложения, идентификатор попытки и её состояние. Новый скрипт не передаёт дизайнеру телефон, токен или банковскую ссылку. Вход и платёжные API принадлежат существующему модулю PadlHub.

## Для разработчика

```js
await window.phSubscriptions.refresh();
window.phSubscriptions.getState('friendship');
// { status, data, checkoutReady, checkoutError }
window.phSubscriptions.refreshBindings(); // перерисовать изменённые классы/data-привязки без запроса или покупки
window.phSubscriptions.openCheckout('ra'); // загрузить/открыть UI выбранного предложения; покупки не создаёт

window.phSubscriptions.destroy();
// true: обработчики сняты, исходные тексты и атрибуты восстановлены.
// false: оформление сейчас обрабатывает запрос; дождитесь результата и повторите destroy.
```

Событие `padlhub:subscription` на root содержит только публичные данные карточки: `event.detail.key`, `event.detail.state`. Это не событие оплаты.

Модуль витрины после загрузки также предоставляет:

```js
window.LKWidgetSubscriptionStorefront.openCheckout('friendship-year');
window.LKWidgetSubscriptionStorefront.openCheckout('atlanty'); // ДРУЖБА.АТЛАНТЫ, 6 800 ₽
window.LKWidgetSubscriptionStorefront.closeCheckout();
window.LKWidgetSubscriptionStorefront.resumeCheckout();
```

`openCheckout` только открывает интерфейс. Он не принимает произвольный productId, цену, телефон, токен или банковскую ссылку. Одновременно открыто одно окно. `closeCheckout` возвращает false во время обработки операции. Не вызывайте `mount()` для дизайнерского блока — это метод полной витрины.

## Приёмка на опубликованной странице

- Загружаются правильные цены и отдельный годовой счётчик; все мобильные дубли размечены.
- Кнопка каждого предложения открывает его точное название и период без перехода на sub_hab.
- При отсутствии сессии доступна форма входа; после входа ожидается явное подтверждение оплаты.
- Годовой тариф нельзя оформить без отдельного согласия.
- Нулевой остаток, неполный ответ или ошибка API блокируют оформление.
- Модальное окно помещается на телефоне, прокручивается, удерживает фокус; Escape и крестик закрывают его вне обработки запроса.
- После закрытия фокус возвращается к кнопке карточки.
- Возврат из банка не создаёт вторую покупку и не объявляет успех по URL.
- На странице нет второй старой вставки, DEV-модуля рядом с PROD или стороннего обработчика на тех же кнопках.

## Подготовка комплекта и локальная проверка

Для разработчика проекта:

```sh
npm run build:subscription-storefront
npm run build:subscription-storefront:dev
node scripts/package-zero-block.mjs /private/tmp/padlhub-zero-block-v2
node scripts/preview-zero-block.mjs # ?main=1 — main lazy fixture, ?auth=0 — вход
node --experimental-strip-types --test scripts/tests/subscriptionStorefrontPromo.test.ts scripts/tests/subscriptionStorefront.test.ts
node --test scripts/tests/mainSubscriptionsZeroBlock.test.mjs
```

Локальный preview на 127.0.0.1:5197 перехватывает все fetch-запросы и использует синтетические вход/платежи. Он проверяет интерфейс, а не подтверждает работоспособность живого эквайринга. Примеры query: `auth=0`, `auth=1`, `fail=timeout`, `fail=status`, `paid=1`.

Владелец: PadlHub. Аудитория: посетители Tilda-лендингов. Ожидаемый результат: выбранная карточка открывает вход и оформление на той же странице. Сигнал остановки: неверный тариф/цена, смешение каналов, повторный POST или непроверенный результат. Способ остановки: убрать новую вставку T123 с лендинга; это останавливает новые открытия, но не отменяет уже отправленные покупки.


## Резидентство и Дружба 2.0 (адаптер 2.2.0)

Владелец подключения — LK. Аудитория — покупатели двух точных подписок Viva.
Генератор `node scripts/package-zero-block.mjs /absolute/output/path` теперь создаёт
`T123-Резидентство-и-Дружба-2.0.html`. Вставьте его целиком один раз после своих
Zero Block вместо старой вставки на этой странице. Для смешанного каталога перечислите
все нужные предложения в одном `offerKeys`, не добавляйте второй init.

| Поле | Резидентство | Дружба 2.0 |
|---|---|---|
| offerKeys | `residency` | `friendship-two-hours` |
| Цена | `ph-price-residency` | `ph-price-friendship-two-hours` |
| Статус | `ph-status-residency` | `ph-status-friendship-two-hours` |
| Кнопка | `ph-buy-residency` | `ph-buy-friendship-two-hours` |
| Карточка, необязательно | `ph-card-residency` | `ph-card-friendship-two-hours` |
| Точный продукт | `4037a3a3-e551-4f9a-a9db-1410e46b8635` | `6b98e7e3-5bd3-4e94-9dc3-7723ea52513e` |

Классы задаются без точки. Для цены начальный текст `—`, для статуса — «Проверяем
доступность…». Кнопке задайте `#`, текст — «Оформить». Разметьте и мобильные дубли.
Период — отдельный элемент: для резидентства `/ 30 дней со дня покупки`, для Дружбы 2.0 `/ 30 дней`. Оба предложения не показывают счётчик продаж;
не рисуйте «Осталось 0». Дружба 2.0 не использует `ph-buy-friendship` и не заменяет
месячную или годовую Дружбу. Алиас с подчёркиваниями в `offerKeys` не поддерживается.

Цена читается без кеша из публичной карточки точного Viva-продукта общим runtime: явная discountPrice, если она есть, иначе cost; проценты самостоятельно не рассчитываются. Для Дружбы 2.0
дополнительно проверяются точные productId и `counterKey=friendship_two_hours`, цена и
`bindingReady/canPurchase` серверного статуса; проверяется область действия продукта.
Для резидентства используется публичная схема subscription resource и область типа
«Резидентство» (2572), а не выдуманный summer counter. Публичный GET подтверждает
цену/условия, но не содержит административного флага видимости продажи. Принятие
прямой транзакции остаётся у Viva; получение цены не является подтверждением покупки.

Перед отправкой покупки цена и параметр активации читаются заново. При изменении
нужно обновить данные и явно подтвердить предложение ещё раз. Сумма ответа транзакции
должна совпасть с показанной ценой до перехода в банк. Нет автоматического POST после
входа, возврата от банка или обновления карточки. Общие Web Lock, retries:0 и долговечный
маркер попытки сохраняются. Восстановление открывает тот же ключ; для прямых продуктов
результат проверяется в кабинете/поддержке, не через confirm старой Дружбы.

Новым ключам необходим обновлённый runtime с `supportsCheckoutOffer(key) === true` и
`loadCheckoutOfferPrice(key, signal)`. Старый runtime закрывает кнопку и показывает
сообщение об обновлении. Новые карточки не используют резервный переход к обычной
Дружбе, даже если включён общий `fallbackToCatalog`. PROD/DEV остаются отдельными.
Вставка не меняет глобальные обработчики авторизации или оформления других продуктов.

Публичные GET 10.11.2026 показали: резидентство 790 ₽, 30 дней, activationDays=0;
Дружба 2.0 — 19 800 ₽, 30 дней, activationDays=1. Владелец подтвердил: резидентство действует 30 дней со дня покупки; изменение activationDays=0 закрывает оформление. Цены не зашиты в адаптере. Эти чтения
не подтверждают реальную транзакцию, начало срока действия, льготы/пропуск резидента
или текущий видимый интерфейс Tilda. Значение visits=30 в карточке резидентства нельзя
рекламировать как 30 бесплатных игр. Не переносите обещания скидок до проверки оферты
и действующих правил резидентства.

Для локальной UI-проверки после сборки:
`node scripts/preview-zero-block.mjs`, затем `http://127.0.0.1:5197/?live=1&auth=1`.
`auth=0` показывает вход; `fail=product` моделирует ошибку карточки. Все запросы этого
стенда подменены, транзакции и вход в настоящие системы не выполняются.

Перед live-подключением нужны согласованная публикация новой пары storefront JS +
release manifest и новой вставки, проверка CORS, браузерного GET и published UI/auth
возврата на телефоне и компьютере. Локальные проверки не заменяют эту публикацию.
Stop signal: несовпадение продукта/цены/условий, ошибка runtime или неопределённый
результат оплаты. Stop method: ошибка до POST закрывает покупку; после неоднозначного
POST остаётся маркер. Для отключения новых входов убрать их offerKeys/вставку в следующем
согласованном обновлении; это не отменяет уже созданные транзакции.


## Прямой путь к банку для двух новых карточек (адаптер 2.3.0)

По решению владельца начальный клик карточки — согласие оформить выбранное предложение
по показанной цене. Исходная учётная запись фиксируется до открытия; смена аккаунта или auth-provider отменяет автоматическое продолжение. В OAuth receipt хранится только одноразовый fingerprint, не токен/телефон. Новый `T123-Резидентство-и-Дружба-2.0.html` включает
`directCheckout:true`. Для `residency` и `friendship-two-hours`:

- Если сессия действительна: один клик → проверка цены/профиля → ссылка банка.
- Если нужен вход: один клик → сразу форма входа → SMS либо штатный OAuth → ссылка банка.
- Во время подготовки виден короткий статус, второй кнопки «Перейти к оплате» нет.
- Если цена/условия изменились, требуется явная кнопка оплаты новой суммы; ошибки не
  приводят к автоматическому повтору. Неопределённая отправленная покупка остаётся
  заблокированной существующим durable marker.

Рекомендуемая надпись кнопки карточки — «Оплатить». Цена и период должны быть видны
рядом до клика. Согласия при входе сохраняются; условия резидентства — 30 дней со дня покупки.
Другие предложения и программный `openCheckout()` сохраняют прежнее подтверждение.
Ссылка/hash или обычная загрузка страницы не создают намерение покупки. Доверенный
клик/клавиатура создаёт одноразовый same-tab intent на 10 минут. Перед POST он потребляется;
банк-return всегда открывает только проверку старой попытки, без новой покупки.

OAuth callback остаётся существующим `/lk_new`, без расширения Keycloak redirect allowlist.
После успешных state/PKCE/code exchange и синхронизации согласий он сохраняет одноразовый
receipt, связанный с opaque intent ID/state/return path. Только этот receipt разрешает
продолжение после редиректа. Restore старой сессии или общий AuthForm.onLogin не служат
такой авторизацией. SMS/phone-completion дают сигнал только после фактически успешного
interactive login/verifyPhone. Close отменяет неиспользованное намерение.

**Публикация требует одновременно обновлённого storefront runtime и основного ЛК,
принимающего OAuth callback, плюс новой вставки 2.3.0.** Это изменение исходников,
не свидетельство нового production deploy. Старый runtime блокирует новый fast-режим;
старый OAuth callback без receipt безопасно возвращает обычное подтверждение оплаты.
Текущая production версия из PR314 остаётся без изменений, пока новый выпуск отдельно
не разрешён. Отключение: убрать directCheckout или вернуть прежнюю T123; это не отменяет
уже отправленные транзакции и не удаляет их markers.
